# 群设置成员预览偶发空白修复

日期：2026-10-05。

## 现象和已确认的客户端原因

用户截图中群人数是 10002，但成员头像区域空白，只显示添加/移除按钮。人数、本人角色与成员列表分别请求，人数成功不代表成员列表成功。

当前源码存在三个可导致该现象的路径：

1. 成员列表在 `LayoutBuilder` 的延迟 builder 内读取，外层 `Obx` 不一定订阅它；群人数已有值时，人数显示也不会读取成员长度。成员请求返回后，成员区域可能不重建。
2. 首次群资料和角色读取被当作权限变化，重复清空预览并发起成员请求；最后一次请求失败时，先前成功结果已经被清除。
3. 原成员请求的异常被空 catch 吞掉，页面没有加载、错误或重试状态，因此 HTTP 失败也只显示一片空白。

没有读取用户设备此次请求日志，不能仅凭截图确认当时是否存在具体网络/服务器错误。

## 修改范围

- 新增 `lib/pages/chat/group_setup/members/group_member_preview_controller.dart`，独立管理少量预览请求、同 scope 请求合并、加载/失败、一次延迟重试和过期响应保护。
- `group_setup_logic.dart` 保留现有 SDK 订阅和权限上下文；首轮元数据及角色初始化不再重复重置成员。真实权限事件、离群和关闭继续清理旧资料。
- `group_setup_view.dart` 在成员区域建立局部响应式订阅，加载时显示六个头像占位，首次错误/空结果可以点击重试。同权限范围普通刷新失败时继续显示已有头像。
- 更换 scope 立即清空旧预览；旧响应不能关闭新请求的加载状态或覆盖新请求的错误。
- 仍使用现有 IM HTTP 成员接口，第一页 20 人，原权限过滤和 `userID`/`account` 分离不变，没有 SDK 账号字段兜底。没有全量成员请求或跨页面持久化缓存。

参考 99chat 的群资料页成员加载占位及缓存保留行为；复用现有 `CircleAvatar`、`Styles`、`AvatarView` 和 GetX，没有新增公共骨架组件。局部私有圆形占位用于现有公共包没有提供等价头像骨架的情况。
