# 公告发布错误提示与溢出修复

2026-10-05，根据用户的 Flutter RenderFlex 日志和公告编辑页截图修复。

## 根因

原公告发布失败直接调用 `IMViews.showToast(error.toString())`。原生 SDK 的 `PlatformException(10000)` 包含 HTTP 地址与 Go 调用堆栈，原 EasyLoading 以没有行数上限的 Text 放在固定外边距的 Column 中，长文本超过视口产生底部溢出。

公告栏的固定前缀另有受限宽度风险：大字号或窄父容器时，前缀加固定间距和关闭按钮会挤压正文。本次限制前缀剩余宽度；原日志中的 0.129px 右侧溢出没有提供对应 Widget 栈，不能确定它来自公告栏。

## 修改

- 公告发布继续使用原 SDK。网络超时显示「请求超时，请稍后重试」，网络/权限错误复用已有短提示，未知错误显示「公告发布失败，请稍后重试」。原生详情只写诊断日志。
- 失败保留原公告和编辑草稿，恢复按钮；提交同步防重入，完成前保留退出保护。已移除或切换群的页面不写入迟到结果。
- 扩展原 EasyLoading 动画：文本最多三行并显示省略号，避让安全区/键盘；高度不够时只缩小内容，保持原遮罩、点击穿透、定时与替换行为。没有修改依赖缓存或新增 Toast 实现。
- 公告栏正常宽度保持原布局，仅在窄宽度时约束前缀、间距及关闭区域。原已读、展开、关闭和跑马灯流程继续复用。

## 网络排查边界

当天只读检查 `8.217.191.236:10002`：根路径和 `/health` GET 返回 404，公告接口 OPTIONS 返回 200，首包均约 0.1 秒。只证明 HTTP 入口当前可达；没有对真实群公告发送 POST，没有读取用户 token，没有证明公告写入、RPC 或数据库流程正常。

SDK 10000 的 `context deadline exceeded`/`Client.Timeout exceeded while awaiting headers` 表示写入请求等待响应头超时，不能据此断言公告未写入。当前工作区没有该 OpenIM 群 API 的 Go 后端源码；服务端超时需结合当次 operationID/时间戳排查 API→RPC→数据库与通知耗时，并读取最新群详情核实公告实际状态。
