## 客户端

去掉厅选择列表、切换按钮及最近选择记录。“查、团、个”直接进入群固定所属厅，页头显示“所属厅：厅名”。加载时校验服务端唯一归属与私有能力 tenantID 一致；空列表、多厅或身份不一致停止加载，不任取一个厅。个人资料继续嵌入既有详情页面，保留运行上下文的生命周期保护。

对照 99chat `d7c3c655b20dd06458d1882b114e68c1c24133e3` 的 `AgentRebateApi.fetchEntryContext` 按登录用户和群定位厅的行为。复用现有三类代理页面、厅名栏、返回按钮、主题和权限保护；没有新增独立业务页面。输入群 ID 的说明明确“一个代理群只对应一个厅”。正式数据来自 Go v2 归属和代理接口。

## 服务端

迁移 039 创建 `sangong_go_group_halls`，群 ID 为主键；个人代理归属及旧群级绑定用复合外键引用同一群＋厅。个人设置、旧群级设置和新建下注群配置通过共同的群归属锁保护，跨厅并发只能有一个厅成功。已有其他厅归属时返回 `AGENT_GROUP_ALREADY_BOUND`，不会覆盖旧绑定、余额或流水。

清除或更换个人绑定后，仍有其他个人/群级绑定或该群仍是下注群时保留归属。不存在任何这些引用时释放空群；重新归属后旧页面通过 tenantId/expectedTenantId 校验被拒绝。私人代理资格、本人及授权下级的数据边界保持原规则。

保留 `A/tenants` 和 tenantId 参数以兼容已发布版本，但前者最多返回一个厅，后者仅核对固定归属，不能切换。私有能力返回固定 tenantID，不再要求选厅。异常多厅数据直接报冲突。
