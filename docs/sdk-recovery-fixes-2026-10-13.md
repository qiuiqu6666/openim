# SDK 离线恢复、弱网补拉与接收修复

2026-10-13。客户端修复已写入当前 Flutter 工程；原生修复已写入与锁定版本一致的受控源码，并导出可重复应用的补丁。当前 App 的 Maven AAR、iOS Pod 依赖没有替换，原生修复尚未进入手机二进制。

按用户要求，没有构建、运行测试、analyzer、安装设备包或新增性能采集。本文的前后对比来自源码行为与既有日志；不能据此声称卡顿、补拉耗时或发热已得到实测改善。修复前证据见 [审计记录](sdk-recovery-receive-audit-2026-10-13.md)。

额外保护：被覆盖页不因同步结束重新加载列表；新绘制前不清空整个会话未读。若恢复提示到达时请求仍在途，待 loading/error 状态全部更新后再检查，避免错过失败结果。日期定位重试自身创建的新窗口编号不会重置两次上限；用户切换到其他窗口后停止旧动作的重试。单聊接收过滤核对明确提供的接收账号，避免旧账号的迟到消息串入新账号。通知内回复改用共享本地消息入口，保留既有通知和本地发送流程。

## 原生交付与剩余边界

受控原生基线为 `v3.8.3-patch.12` / `101cf038eb114bc58bd9298dedeff33e3b1a73f2`。[补丁与接入说明](../native_sdk/README.md) 提供基线校验、补丁哈希和可重复应用脚本。原生二进制尚未接入，因此 R04–R07 和 R08 的锁修复不能标记为手机端已生效。

恢复成功依然只说明本轮最新摘要和相应必要步骤完成，不代表所有离线历史已下载。服务端权限、退群、历史下限和消息删除政策仍由上游决定。好友/群通知的既有 void 接口没有完整错误返回；跨表部分写入、极端 DB 阻塞、旧原生调用永不回调，以及未知外部重排仍是后续验证边界。错误消息正文不再静默作为成功处理，但本轮没有新增坏记录隔离或跳过策略；持续解析失败可能阻止该批推进并在恢复周期再次补拉，需根据具体数据或协议错误处理。处理回执使同步工作等待接收处理，应在高消息量场景核对吞吐和队列等待，不能只根据减少重复请求推断总体更快。

允许后续构建和采集后，应优先验证：A→B→A 叠加聊天与回执；延迟旧消息到达；Wi-Fi/蜂窝切换与网络类型不变的弱网；长时间后台恢复；分批拉取/消息落库失败后重试及重启；大量会话删除/取消置顶时分页；日期窗口失败恢复和返回最新。比较同账号、同消息量、同设备、同 Release/Profile 条件，记录首次可见时间、补拉完成事件、消息 ID/SEQ 完整性、重复回调、真实在途数、锁等待与掉帧。
