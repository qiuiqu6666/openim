# SDK 日志策略

默认精简模式抑制正常命令入队、普通接口调用开始/成功、成功 WebSocket 响应、心跳、订阅开始和会话刷新流水。错误、异常响应、连接状态变化、消息同步结果及性能汇总仍保留。成功接口耗时达到 1 秒时保留原有成功记录与耗时字段。

临时详细诊断通过原生 SDK 导出接口控制：

```go
open_im_sdk.SetDiagnosticLogging(600) // 开启 10 分钟；返回实际接受的秒数
open_im_sdk.GetDiagnosticLoggingSeconds() // 查询剩余秒数
open_im_sdk.SetDiagnosticLogging(0) // 立即关闭
```

最长 900 秒；非正数关闭；再次开启从当前时间重新计时。使用单调时钟与原子状态，无后台计时协程，不持久化，进程重启默认关闭。到期后输出点自动停止详细日志，无需额外调用。

初始化日志级别应保持 Info（4）或更详细；此开关不会提高底层日志级别，不打开 Debug/SQL 日志。详细模式恢复上述流程元数据，接口仅输出函数名、参数数量与耗时，不增加参数或消息正文输出。现有其他日志的脱敏不在此开关范围内。

Flutter 设置 → 日志诊断已接入 Android/iOS 原生桥接。页面默认开启 600 秒，读取原生剩余时间，后台停止刷新，回到前台重新查询。recovery.44 Android 原生库已重建；iOS Framework 仍需在 macOS 重建，旧二进制不包含这些导出接口。

验证：窗口默认关闭、到期边界、续期、立即关闭、上限与并发访问；命令实际入队不变，精简模式抑制成功日志，详细模式恢复成功日志，错误始终输出；公共接口开启/关闭测试及消息同步竞态回归。
