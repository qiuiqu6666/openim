# 收藏功能前端实现与联调说明

本文件记录 2026-10-03 按早期设计实现的历史状态。用户于 2026-10-04 提供了更具体的 P0 部署契约；**当前开放范围、接口与验收以[收藏 P0 前端对接](favorites-p0-integration.md)和[最终契约](favorites-client-contract.md)为准**。下文的标签及其他复杂类型能力不代表当前已开放。

2026-10-05 交互已调整为左侧查看/播放、右侧按钮发送；下文早期“点击已就绪收藏直接发送”的描述为历史实现。当前行为及修复包见 [收藏媒体预览](favorites-media-preview-2026-10-05.md)。

## 1. 用户操作

| 入口 | 操作与结果 |
| --- | --- |
| 聊天消息长按 → 收藏 | 服务端依据原会话、消息编号授权并归档；显示保存中或已收藏 |
| 我的 → 收藏 | 获取本人云端列表；支持分页、搜索、类型/标签筛选、详情、删除、批量删除 |
| 收藏页面 → 添加 | 创建文字笔记、链接，上传图片、视频、音频或文件原件 |
| 收藏页面 → 标签 | 创建、改名、删除私人标签；为单项或多项分配标签 |
| 收藏详情 → 编辑 | 编辑纯文字笔记，保存失败保留输入；版本冲突提示刷新 |
| 收藏详情 → 重试保存 | 重试服务端归档失败的收藏 |
| 聊天加号 → 收藏 | 显示固定发送目标；点击已就绪收藏直接发送，预览按钮仅查看 |
| 收藏详情/长按 → 发送到对话 | 复用现有联系人/群/会话选择器，发送到所选目标 |
| 收藏页面 → 编辑 → 多选 → 发送 | 选择目标一次，按收藏和目标顺序发送；中断后保留同一选择继续未完成部分 |

收藏快捷发送保留聊天输入文字、草稿、引用和 @ 状态。媒体发送的是 SDK 新建消息，发送后的聊天资产独立于私人收藏。

## 2. 内容支持

| 内容 | 保存/查看 | 快捷发送 |
| --- | --- | --- |
| 原生文字、引用正文、@ 正文 | 消息收藏或笔记 | 新文字消息，不重建原引用或 @ 通知 |
| 图片、视频、语音、文件 | 原件上传或服务端消息归档 | 下载授权原件、校验后由 SDK 重新上传 |
| 链接 | 保存 URL、查看详情 | 发送 URL 文字 |
| 定位、名片 | 收藏现有原生消息、查看字段 | 新原生定位/名片消息 |
| 服务端已有图文笔记/消息合集 | 按顺序查看 blocks | 白名单 blocks 逐条发送，保留部分发送进度 |
| 未知类型/未知 schema | 显示兼容状态 | 不发送 |
| 红包、转账、交易/通话控制、自定义协议、阅后即焚 | 不开放消息收藏入口 | 不重放 |

**尚未开放的设计项：**多条聊天消息合并创建收藏、图文笔记的完整 block 编辑器、原生媒体 merger 和独立分享卡片。原文档没有给出多消息创建的最终 locator-list 请求结构，也没有定义分享卡片客户端 wire discriminator 与兼容协议；这些不能靠前端猜测。已有复杂收藏采用文档允许的逐条发送方式。完整设计文档的 P1 整体仍需后续验收，当前交付不宣称已完成所有 P1 能力。

## 4. 接口与发送流程

业务请求基地址为 `Config.appAuthUrl`，使用 `token: DataSp.chatToken` 与独立 operationID。SDK 的 IM 登录、上传、消息发送仍走现有 SDK 链路。

主要业务接口：

- `GET/POST /chat/favorites`
- `GET/PATCH/DELETE /chat/favorites/{id}`
- `POST /chat/favorites/{id}/retry-archive`
- `POST /chat/favorites/uploads`、`POST /chat/favorites/uploads/{uploadID}/complete`
- `POST /chat/favorites/{id}/asset-access`
- `POST /chat/favorites/{id}/prepare-send`
- `GET/POST /chat/favorite-tags`、`PATCH/DELETE /chat/favorite-tags/{id}`

数据层另提供 `changes` API；当前列表通过刷新、分页和归档详情轮询更新，尚未启用常驻后台增量同步。

发送步骤：

1. 冻结当前目标，获取详情与不可变 `contentRevision`。
2. 调用 `prepare-send` 获取白名单发送内容和短期下载授权。
3. 使用独立无业务 token 的媒体客户端下载，校验真实字节数和 SHA-256；视频同时取得封面，音视频时长转换为 SDK 使用的秒。
4. 由 SDK 创建全新 Message，持久保存原 `clientMsgID` 后再提交。
5. 根据 SDK 结果逐块记录成功、明确失败或未知。成功块不会在续发时重复提交。
6. 批量发送在提交前保存每个“收藏 × 目标”的固定 attemptID；恢复时已成功任务返回原成功结果，继续未完成目标。

不把 `favoriteID`、原会话来源、私人标签/备注或签名下载 URL 填入接收者消息。业务异常和 SDK 异常采用安全文案，不展示原始异常中的私有 URL/token。

## 5. 网络和生命周期处理

- 保存中的媒体禁止快捷发送；归档成功后再开放。
- 无网络时保留本人轻量列表缓存，显示缓存和请求错误；列表摘要不含原件或下载凭证。
- 创建和修改响应未知时沿用原 clientRequestID；已完成上传的资产可用于创建重试，避免重传原件产生不同请求正文。
- 请求 ID 和已完成上传记录必须先成功写入本地，再提交对应请求；写入失败时提示检查设备存储，不发起该请求。展示缓存写入失败不会把服务端已确认成功的操作误报成失败。待处理请求键使用 SHA-256，不保存笔记全文。
- SDK 网络超时不是明确发送失败，不生成新的消息编号重发。
- 选择器“核实发送结果”仅查询原 ID；本地失败状态或查询不到消息仍保持未知。仅同账号、同目标、成功状态且存在服务端序号的记录可确认。
- 某块已确认发送、后续块失败时，下一次主动续发仅处理剩余块；核实本身不自动发送下一块。
- 批次第一项明确被拒绝且没有任何已接受内容时，结束旧批次并提示刷新/重新选择，避免旧修订永久锁住发送。部分成功或未知批次可主动取消剩余发送；取消不撤回已发消息，且保留未知消息的防重复记录。
- 气泡上的失败重试也保留当前输入；收藏消息重试仍经原发送任务，已成功任务不会再次提交。
- 账号退出/切换会取消旧业务请求，清除当前内存列表和 UI 状态；旧账号迟到响应不会进入新账号界面。
- 搜索采用防抖和请求代次，旧查询响应不能覆盖新查询。
- 编辑/删除/标签更新带 expectedVersion，发生冲突保留当前内容并提示刷新。

源码静态检查与模拟 SDK/HTTP 测试不等于已验证部署服务和真机 SDK 上传。当前工作区还不能据此宣称整包可编译或已完成上线验收。

上线前需用两个测试账号在 Android/iOS 验收：

1. 单聊与群聊分别收藏、发送文字/图片/视频/语音/文件，并在接收端打开原件。
2. 比对原视频播放、封面、语音时长、文件名与 hash；单独验收 GIF/HEIC 和当前 SDK 的媒体限制。
3. 在网络中断、发送超时、强退重启、群禁言/退群时检查结果及续发。
4. 确认快捷发送保留已输入草稿、@ 和引用，连续点击只产生一次发送。
5. 删除私人收藏后，确认已发聊天附件仍能打开。
6. 编辑/删除/改标签后用另一设备刷新验证真实云端状态，账号切换确认私有缓存不串号。
7. 未知结果查询不到时维持待确认状态，不能用“本地 failed”作为允许新 ID 重发的依据。

本次未替换 OpenIM SDK、路由或聊天状态框架；已有聊天发送仍复用 SDK 传输。正式后端网络联调、真实接收端资产访问和 iOS/Android 原生播放器行为仍需上述设备验收。
