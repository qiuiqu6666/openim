# 群直播真实接口测试记录

测试时间：2026-10-05；服务地址 `http://8.217.191.236:10008`。

使用当前 Android 模拟器的真实登录会话，用户接口携带 `chatToken` 和独立 `operationID`。没有把令牌、推流密钥或完整签名播放地址写入此文档。测试使用两个仅含当前账号的临时群；测试场次已撤销、临时群已解散，推流进程已关闭。

## 结论

创建、预约、修改、读取、凭据签发和撤销的基本接口正常；真实 RTMP 推流及 HLS 音视频读取也成功。**完整开播链路尚未通过**：推流持续观察 45 秒后，业务场次仍为 `AUTHORIZED`，没有进入 `LIVE`；合法 JSON 群扩展也未出现直播摘要。应继续检查云回调和 OpenIM 镜像同步，不能将“创建成功”视为“直播业务已正常开播”。

## 基础接口结果

| 测试 | 实测结果 |
| --- | --- |
| 创建前 current | `errCode=0`，`active=false` |
| 创建前个人能力 | 配置／管理／打赏允许，`canPush=false`；三公／六合彩关闭 |
| 空名称、11 字名称、31 字描述、过去预约、不足一分钟预约、非群成员主播 | 均返回 `1001`，未创建场次 |

| 创建后个人能力 | `canPush=true`，个人版本从 0 到 1 |
| 重复创建 | `20069`，未产生第二个活动场次 |
| push-info / play-info | 均为 `errCode=0`，有效签名、未来 `expiresAt`；没有输出签名内容 |
| 撤销 revoke | `BANNED`、`endReason=revoked`，完整摘要 ended，`pending` |
| 撤销后 current / 能力 | `active=false`，`canPush=false`，个人版本继续前进 |
| 创建预约 | `SCHEDULED`，UTC 预约时间正确，完整 scheduled 摘要 |
| 修改预约 schedule | 同场次，名称／时间更新、版本前进；主播／描述保留 |
| 重复撤销／对终态调用 stop | `errCode=0`，保留原场次和终态；响应缺少 `imSyncStatus` |
| 无有效签名腾讯云回调 | HTTP 403、`20012`，状态不变 |
| 不存在场次 detail | `20068` |
| AUTHORIZED 直接调用 tip，支付密码为格式合法的假值 | `20035`；支付密码校验先触发，尚未验证状态拒绝 `20070`；未成功打赏 |

基础轮共执行 35 项检查。31 项严格符合断言；其余 4 项为 3 次成功响应缺少同步元数据及 1 次校验顺序差异，不是 4 个接口功能失败。当前前端接受合法终态及完整摘要，不会因缺少 `imSyncStatus` 将重复撤销误判失败。

## 真实云端推流与同步

第二个测试群创建时，`ex` 已是合法 JSON 对象并含无敏感信息的测试标记，排除了“旧 ex 非 JSON，服务端保留原值”的特殊情况。

使用签发的 RTMP 地址向腾讯云发送临时测试彩条和静音音轨，320×180、15 帧／秒，约 192 kbps。未提交伪造的合法开播回调。

| 检查 | 证据／结果 |
| --- | --- |
| 腾讯云 RTMP 接收及媒体传送 | 45 秒观察时已发送 727 帧，编码进程仍运行，无编码／推流错误 |
| 实际 HLS 媒体读取 | 成功解析 `h264` 视频（320×180）及 `aac` 音频；实际媒体可读 |
| 业务开播状态 | 45 秒内连续读取 detail，始终 `AUTHORIZED`；未观察到 `LIVE` |
| OpenIM 公共摘要 | 45 秒内 `ex` 始终仅含原测试标记，没有 `groupFeatures`；原标记保留 |
| 场次撤销 | 成功 `BANNED`，`endReason=revoked`，`imSyncStatus=pending` |
| 终态幂等 | 成功返回同场次，但仍不含 `imSyncStatus` |
| 清理 | 无活动场次，临时群已解散；测试推流已停止 |

**影响**：当前前端以真实业务 `LIVE` 开放观看／打赏；业务不推进时仍显示待开播。其他成员的入口和角标依赖 OpenIM 群摘要；镜像未同步时不会收到直播入口。

**待后端核对**：

1. 腾讯云开播回调地址、服务可达性、回调签名、事件解析及流名与场次绑定。HLS 媒体成功不代表回调已经送达或处理成功；本轮未确认具体失败原因。
2. OpenIM 镜像同步任务是否执行、管理员 IM 凭据、部署中的群资料更新路由、失败日志和重试任务。45 秒内未同步是实测事实，最终原因／重试时延需要服务端日志确认。
3. 重复 stop／revoke 的成功分支补上实际 `imSyncStatus`，统一响应结构。
4. 若合同要求非 LIVE 新打赏订单优先返回 `20070`，应在支付密码和扣款前检查状态；或者文档明确密码校验优先，并通过后端单测验证密码通过后非 LIVE 不调用钱包扣款。已提交订单仍按原幂等记录处理。
