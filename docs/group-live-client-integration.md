# 群直播客户端接入

更新时间：2026-10-05。依据用户提供的现有后端《群直播》合同，不修改后端服务。

## 地址、鉴权与入口

请求基地址沿用登录所选服务器的 `Config.appAuthUrl`；当前默认 Chat API 为 `http://8.217.191.236:10008`。请求头使用当前 `chatToken` 的 `token` 和独立 UUID `operationID`，不使用 IM token。业务成功检查 `errCode=0` 和有效 `data`，HTTP 200 本身不能代替成功。

群聊天工具箱和群设置「群功能」进入直播管理；群主、管理员按个人能力创建、改预约和结束。被授权主播按 `canPush` 查看推流信息。成员从群直播条进入内嵌观看和全屏，共用播放器。LIVE 场次且 `canTip` 才显示打赏。

页面继续复用本地 99chat 对应直播页面、图片，以及项目的主题、安全区、OpenIM 群成员选择和资金支付密码组件。没有增加管理员配置页或新登录体系。

## 已接用户接口

| 方法 | 路径 | 数据与用途 |
| --- | --- | --- |
| GET | `/chat/groups/{groupID}/feature-capabilities` | 当前用户能力；缓存最多 300 秒，同群在途查询合并 |
| GET | `/group-live/api/v1/groups/{groupID}/live/current` | `active` 和 `session`，无活动时接受 `active:false,groupFeatures:{}` |
| POST | `/group-live/api/v1/groups/{groupID}/live/authorize` | 名称、主播、描述、预约时间；立即授权传 `scheduledStartAt:null` |
| PATCH | `/group-live/api/v1/groups/{groupID}/live/schedule` | 只修改名称与预约时间 |
| POST | `/group-live/api/v1/groups/{groupID}/live/stop` | 结束 LIVE 场次，接受原终态 |
| POST | `/group-live/api/v1/groups/{groupID}/live/revoke` | 撤销预约或授权，接受原终态 |
| GET | `/group-live/api/v1/live/{sessionID}` | 校准当前业务场次及版本 |
| GET | `/group-live/api/v1/live/{sessionID}/play-info` | 签名 HTTPS HLS 和 FLV 备用、有效期 |
| GET | `/group-live/api/v1/live/{sessionID}/push-info` | RTMP server、stream key、有效期；实时校验当前权限 |
| POST | `/group-live/api/v1/live/{sessionID}/tip` | 当前币种、整数最小单位金额、六位支付密码、稳定订单号和备注 |

名称最多 10 字、描述 30 字、打赏备注 50 字；预约至少晚于当前时间一分钟，展示和选择使用本地时间，提交使用 UTC ISO-8601。币种严格使用能力接口返回且后端支持的 USDT、TRX、BI99，不互换币种码；金额限制 `1～9007199254740991` 最小单位。

## 成功、同步和失败

创建、改预约、结束和撤销直接解析 `data` 的完整场次 DTO，保留 `imSyncStatus`。`pending` 表示业务已保存，页面显示成功并接收后端完整摘要，不再发一次创建。同步待重试时，旧版本或非 JSON 的 SDK 镜像不能清除该已确认摘要；镜像追上版本后恢复正常资料规则。

保存返回后刷新个人能力，解决创建前 `canPush=false`、创建后具备推流资格的变化。角色或主播权限通知会使旧私人快照失效；已打开页面采用新快照。旧推流密钥立即清除，迟回包不能把撤销的密钥放回页面。

| 后端码 | 客户端处理 |
| --- | --- |
| `1001` | 参数提示 |
| `1002`、`20012`／HTTP 403 | 提示权限不足，失效并重新读取个人能力 |
| `20068`、`20070` | 提示场次不存在或状态已变化；观看的明确拒绝停止旧播放器，管理按实际场次校准 |
| `20069` | 提示已有活动场次；只读查询当前场次，不重复创建 |
| `20071` | 提示直播服务尚未配置，请管理员配置直播服务 |
| `20026` | 余额不足 |
| `20034`、`20035`、`20036` | 未设支付密码、密码错误、密码锁定的相应提示 |
| `20062` | 原打赏订单参数冲突；保留待确认订单，不能另起订单重复扣款 |
| 写入超时或成功 DTO 不完整 | 结果尚未确认；创建先查询 current，打赏保留原订单重试 |

合法成功 DTO 已确认提交后，单独的私人权限变化不会把该笔保存或打赏变成未知。账号、令牌、节点、退群守卫仍会拒收不属于当前会话的响应。

## 多端更新与请求数量

进入群聊就查询一次 current 校准公共直播状态，回到前台且未观看时再次校准，SDK 镜像缺少摘要也能显示真实活动场次。有效业务摘要回写账号共享仓库，SDK 群资料事件继续更新条目和角标，不要求服务端新增群业务广播。SDK 镜像缺失或版本落后时保留真实业务摘要，镜像追上后恢复常规校验。主播的定向 `groupFeatureCapabilitiesChanged` 只比较个人 `capabilityVersion`，群摘要 `revision` 独立比较。

群列表和会话行只读账号共享状态。列表协调器按实际可见群去重，以最多 2 并发查询现有单群 current；进入、切回和恢复前台立即校准，通知定向更新。参考 99chat 的 45 秒可见期间兜底，后台、隐藏标签及路由覆盖停止检查；不扫描全部会话、不在行 build 中请求，也不使用不存在的批量直播接口。current 无完整群摘要时只更新真实场次的显示投影，active=false 能移除旧角标，不合成 revision。

观看后才取场次和播放地址；内嵌、全屏共享一个 native 播放实例与签名续签任务。有效期临近时可见播放器提前续签；后台、路由覆盖、离开、结束和换场取消计时及在途读取。播放失败退避，没有固定每秒或几十秒查询场次的播放器轮询。

授权或预约不等于正在直播。页面等待服务端经腾讯云真实推流回调进入 LIVE，再取观看地址及允许打赏。推流页展示 OBS 所需地址、二维码、复制及教程；客户端不会调用腾讯云回调伪造开播。

## 服务端仍负责

管理员在 `10009` 配置 `/live/config`、推流域名、播放域名、签名 Key 及断流凭据。云回调验签、场次状态机、断流宽限、真实断流和资金账务幂等由现有后端完成。这些密钥不进入客户端。

本轮仅启用直播。三公和六合彩能力按服务端返回关闭，客户端保留此前独立模块，但不借直播权限放行游戏操作。
