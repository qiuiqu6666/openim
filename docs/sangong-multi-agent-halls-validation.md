# 同一代理群选择多个厅（历史实现，已替换）

当前规则已按用户要求改为一个代理群固定对应一个厅，无切换入口。下文为上一版本历史验证记录；当前实现见 [固定厅验证](sangong-single-agent-hall-validation.md)。

2026-10-09。同一 IM 用户可以在多个下注厅绑定同一个代理群。每个厅内仍只有一个个人代理群归属；查询、划转、返水和幂等回执均按所选厅隔离。

## 用户行为与模块

进入三公代理先查询本人可查看的厅。单厅自动进入，多厅显示选择页；代理页头显示厅名及“切换厅”。同一次群聊中“查、团、个”记住最近选择，再次进入重新核验列表。被撤销的厅不恢复；子详情固定显示所属厅。未确认写入结果时禁止切厅，供原请求重试或核对。

参考旧 99chat `d7c3c655b20dd06458d1882b114e68c1c24133e3` 的代理总览、团队、个人页及 `AgentRebateApi`。旧实现使用单一厅上下文，未确认有同群多厅选择；新增 `agents/halls/` 组合入口，复用现有三类页面、返回按钮、权限保护、GroupFeatureTokens 和主题组件，不另造代理业务页。正式数据来自 Go v2 `A/tenants` 与携带 tenantId 的代理接口。

每次选择创建独立 SangongRuntime；切换时销毁旧运行上下文、请求和缓存。聊天上下文仅保存选择偏好。个人页采用嵌入详情，避免替换路由时提前销毁所选厅运行上下文。权限快照包括 requiresTenantSelection；所有数据仍由服务端按用户、代理群和所选厅复核。
