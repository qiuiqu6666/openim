# 骰子 WebP 接入验证 · 2026-10-06

按用户最新要求，六份动画 WebP 原样打包，项目中的六个骰子 Lottie JSON 已删除。WebP 均为透明 512×512、181 帧、每帧 16 毫秒，按原始帧时长播放一次（源时间合计 2896 毫秒），随后停在最终点数。实际墙钟时长受屏幕刷新及解码耗时影响，没有人为速度倍率。用户附件第五张实际是 6 点，第六张是 5 点，因此按实际结果映射文件名。

自定义表情四列面板和添加、管理及个人表情项继续复用当前实现。参考 99chat 既有表情入口和布局；参考仓库未找到对应骰子功能。骰子专用渲染需要精确控制一次播放、历史末帧和暂停，因此由公共组件管理 WebP 解码与帧展示。

OpenIM SDK custom 协议保持 `customType: 906`、`version: 1`。随机 1～6 点在创建消息前确定一次；发送、接收、摘要、旧消息和失败重试读取同一个点数。发送中重复点击、禁言、无效群、关闭和账号切换均有保护。无需上传资源或新增后端接口，也没有修改其他 custom 消息的菜单权限。

公共渲染沿用既有表情尺寸、透明容器和真实消息时间/状态覆盖层。离屏、应用后台、路由覆盖和禁用 TickerMode 时暂停，恢复后继续原进度。未完成的列表行短期重建复用解码会话；历史、合并记录、完成后的重建和减少动画直接显示最终帧。亮暗主题均使用素材原有透明通道。

针对用户录屏中转动过程卡顿，本次将总时钟批量追帧改为提前解码下一帧、按原时长逐帧展示。解码较慢时不会丢弃整段中间画面或强制跳到结果。运行时仅保留当前与下一帧；短期无人使用的会话保留五秒，最多六个，过期后不重播。六个静态末帧以无损单帧 WebP 导出，完整 RGBA 与原动画末帧一致；历史和面板直接读取它们，避免首次静态加载仍在引擎共享 IO 队列中解码并上传整段 181 帧。原始动画文件 SHA-256 均未改变。

资源审计、来源与 SHA-256 见 `openim_common/assets/chat/dice/README.md`，职责与开发资源更新说明见 `lib/pages/chat/stickers/dice/README.md`。实际点数和亮暗预览位于工作区 `E:/openim/artifacts/chat-dice/`。

资源清单更换后需要完整重新运行开发应用或安装新 APK。长期热重载会话可能未同步公共依赖包的新增资源；仅热重载代码不能验证设备已有图片。最终检查同时核对资源包中存在六个原动画和六个静态结果 WebP，且已无骰子 JSON。

验证结果：

- 全部表情模块、两组消息菜单与会话摘要回归共 221 项检查通过。
- 其中 WebP 播放 32 项、面板 10 项通过真实解码和像素比对验证帧时长、原速、透明度、末帧、重建、路由/后台/离屏暂停、异步替换与释放、加载失败和原 SDK 重试。
- 新增逐帧 16 毫秒比对全部 181 帧；阻塞第二次解码后顺序恢复、一次循环只解码 181 次；未完成 State 回收继续第 40 帧；会话过期不重播；解码进行中卸载后原生资源只释放一次。
- 公共骰子组件、内部解码模块、面板/发送模块及骰子测试静态分析无问题。
- 六个旧动画 JSON 已从骰子资源目录删除，骰子代码和测试无 Lottie 引用。
- Android debug 构建通过；最新安装包 `E:/openim/artifacts/chat-dice/app-chat-dice-smooth-webp-debug-20261006.apk` 内含六个原动画 WebP、六个静态结果 WebP、零个骰子 JSON，十二个打包文件 SHA-256 与源资源一致。

本地检查不发送真实消息；用户录屏所用设备的实际流畅度、双设备收发和 iOS 构建尚未验证。源码原速与逐帧顺序检查通过，不将本地测试当作设备录屏验收。
