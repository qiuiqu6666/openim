# 用户活动采集

本模块复用已有 AppController 生命周期、根 Navigator、共享 Dio 和消息发送服务，不改页面外观、SDK 登录或资金执行逻辑。它是新业务采集能力，未作 99chat 页面迁移。

- activity_collector.dart：有界内存队列、事件编号、顺序、重试、前后台、账号隔离。
- activity_schema.dart：页面、动作和 HTTP 路径白名单。禁止上传输入内容、路由参数、正文、验证码、密码、Token。
- activity_runtime.dart：生命周期、设备版本、独立上报传输和 Dio 关联；operationID 与 X-Activity-Session 只用于查询关联。
- activity_sdk.dart：SDK 动作结果记录。成功为客户端报告成功；抛错为结果未确认，原错误继续交给调用方。
- connection_activity.dart：同一凭据会话内的 SDK 连接状态；首次连接不算重连，重复回调去重。IMController 提供连接回调，Splash 在保存凭据恢复成功后标记 session_restore；登出、账号替换清空。事件使用独立的 connection 类型，不伪造登录、点击或前台活动。

每 5 秒尝试合并发送，每 30 秒前台心跳，交互信号最多每 30 秒一次；后台不产生心跳。单批最多 40 条，内存最多 200 条；失败退避 30/60 秒，溢出丢弃最早数据。退出、Token 或账号变化会取消上报并清空内存，迟到请求不能清除新账号队列。不上报磁盘缓存，因此断网、系统杀进程可能造成缺失。

单次连续活动超过 30 分钟且队列已清空后创建新的活动区间，使用心跳延续，不额外制造进入前台次数或页面访问次数。页面时长由服务端接收间隔近似计算；不把后台长时间挂起计算为活跃。

新增页面使用已有导航的 activityPage 参数或 activityRoutes 白名单，不使用运行时类型、动态路由名或用户输入。弹窗不改变当前页面。新增 SDK 操作使用 observeUserActivity，并保留账号所有权检查。新增接口只在固定本站路径、当前账号 Token 匹配时关联；上报使用独立 Dio，失败不会触发退出或业务重试。

测试：test/core/user_activity/。导航、消息、申请等接入点另运行原有回归测试。Android/iOS 均共用 Dart 生命周期和采集；该服务器没有 Android SDK / iOS 构建环境，平台安装包和真机前后台仍需客户端发布流程验证。

连接观察在后台单独显示“恢复登录状态 / 连接中断 / 断线重连”，标注客户端上报，不增加今日登录次数。升级前的登录历史不按设备名、IP 或时间接近猜测为重连。新版后端先发布后再发客户端；仅发布后台不能让旧 App 补报重连。
