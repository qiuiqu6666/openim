# 申请通知对接（2026-10-14）

仅 `onFriendApplicationAdded` / `onGroupApplicationAdded` 进入专用同步事件流，其他申请变更继续刷新列表。AppController 持有订阅、通知运行时及生命周期，复用现有本地通知插件初始化和权限流程。

## 当前行为

- 前台且登录、通知设置、SDK 同步已就绪时，验证接收列表中仍待处理的申请，再显示系统本地提醒。群申请另查当前成员角色，只允许群主/管理员。邀请场景使用申请记录的 userID/nickname。
- 后台不额外生成本地提醒，交给现有个推/APNs，避免与系统离线通知重复。iOS 现有 AppDelegate 在前台抑制远程系统展示，前台提醒由本运行时负责。
- 尊重全局免打扰、前台通知开关、预览隐私、声音/震动设置。当前正查看对应申请页时不提醒。没有申请审批快捷动作，不影响聊天会话未读。
- 去重键由类型、申请人、群、申请时间组成，按账号持久化最近 512 条；内存也记录被抑制回调，避免同一事件在恢复前台后重放。没有时间、早于本次前台同步就绪点或超过 60 秒的事件仅刷新状态，不补弹旧通知。秒/毫秒时间统一处理。
- 启动、恢复前台、同步结束刷新申请红点；打开的申请页也在恢复/同步结束刷新。好友继续用 SDK，群申请页和红点保留工作区已有的 `GroupNoticesApi` 服务端可见性接口；提醒校验使用 SDK recipient 列表和成员角色。

## 点击边界

本地通知使用客户端专用 `type: local_application` 载荷，经现有通知回调分流。保存点击后等待会话/SDK 就绪，核对账号与会话指纹，打开申请列表查询最新状态。重复点击不重复入栈。

服务端建议的 `friend_application` / `group_application` 协议尚未上线，本次不接入该远程协议。Android `startapp` 和 iOS 旧 `ex` 保持现有安全回退；绝不匹配中文标题决定路由。远程精确跳转需服务端补齐结构化载荷后联调。

## 验证

自动测试覆盖接收人/角色、已处理/自己发出、昵称与群名回退、邀请场景、免打扰、历史同步、去重、账号切换、关闭后迟到结果、本地点击等待与旧协议回退，以及页面/红点刷新。真机个推/APNs 离线弹窗、系统权限关闭、后台与冷启动点击仍需 Android/iOS 联调。
