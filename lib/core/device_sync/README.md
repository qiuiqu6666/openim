# 相册与定位同步

设置页面实现为「相册与定位同步」，位于 `lib/pages/mine/settings/device_sync/`；2026 年 10 月 11 日核对时设置首页没有接入该入口，相关既有用例失败。账号没有保存偏好时，照片、视频、后台定位、仅 Wi-Fi 相册同步四项默认开启；缺少已保存选择的开关也按开启处理，明确保存的关闭选择继续保留。首次登录不显示应用内同意弹窗；手动重新开启视频仍需单独确认。同步仅使用系统已经允许访问的相册与后台定位权限，没有系统权限时跳过。同步只允许在应用后台执行，相册默认只用 Wi-Fi，定位每次进入后台只获取一个新点。

## 调度与取消

- 登录、SDK 就绪及页面跳转只准备调度，不等待媒体上传。应用在前台时，即使静置也不扫描相册、不获取同步定位、不上传；退到系统后台并静置 5 秒后才允许执行。
- 后台保留的聊天路由不阻止同步；来电/通话仍让路。前后台切换立即改变同步资格，不等待提示音等异步资源释放，避免旧后台回调在返回聊天后重新开启同步。
- 每页 24 条元数据，一次处理一个文件/分片；原件不做图片解码、压缩或全量内存读取。每个文件后主动让出 100ms。
- 回到前台、触摸、退出账号或改设置立即取消本轮，取消令牌传递到定位订阅、哈希任务及网络上传。晚到结果不得标记完成；下一次后台执行重新采集新定位，同时保留待传定位及分片续传记录。
- 设置选择在等待磁盘前同步生效。持久化暂时失败会保留用户的内存选择并延后重试，不将用户关闭的开关恢复为默认开启。
- 网络失败退避 2–15 分钟，普通触摸和页面就绪事件不会缩短退避。认证失败停用该会话的同步，不注销 IM；凭据变化后恢复。

## 原件和定位边界

- iOS `PHAssetResourceRequestOptions.isNetworkAccessAllowed = false`。仅存于 iCloud 的资源直接跳过，不退回 `originFile` 下载链路。
- GPS 只使用本次采集开始后的新位置。10 秒无结果时停止订阅，该次后台停留内不再采集，也不发送以前排队的位置来替代。有效定位后的网络重试保留原 clientID 和经纬度；下次进入后台获得新位置时可重试旧的持久化点。
- 同步定位只接受系统已经授予的 `LocationPermission.always`，不使用仅前台授权启动后台采集，也不自动申请新权限。iOS 为有权执行的一次定位启用后台定位能力，返回前台或采集结束即取消订阅；聊天中主动发送位置的功能不受影响。
- 关闭定位清除待传定位与未持久化的临时位置；关闭相册保留已完成标记以避免将来重复上传。
- `probe/ticket/finish` 只有服务端确认 `done` 才记本地完成；未完成分片用同一 localID 重取 ticket，跳过 doneParts。文件内容冲突使用含内容哈希的稳定替代编号。
- 当前是仅后台允许执行的进程内队列，实际运行时长受系统后台限制。系统挂起或终止进程后不保证继续上传，没有接入 Android WorkManager 或 iOS 后台 URLSession；重新运行后仍需退到后台才能继续未完成的任务。

## 四项默认开启（2026-10-06）

- 未保存偏好的账号及缺少已保存开关选择的旧账号，照片、视频、后台定位、仅 Wi-Fi 相册同步默认开启；已经保存的各项关闭选择保持关闭。
- 默认开启视频不触发确认弹窗；用户手动重新开启视频时保留既有确认。同步继续仅使用已有系统权限，账号、服务地址和设备隔离规则不变。

## 每次后台定位（2026-10-14）

每次真实的前台到后台切换生成新的定位 clientID；重复后台通知、SDK 就绪及同一轮网络重试复用原 ID。Runner 等待上一次取消的任务结束后才重置采集标记，防止快速前后台切换时旧结果覆盖新一轮。保留 5 秒静置、10 秒新位置超时、系统后台权限及网络退避。前台同步取消定位和上传；照片扫描、分片续传及聊天链路保持原有机制。
