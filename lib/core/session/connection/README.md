# 连接、后台与恢复

连接由 OpenIM 原生 SDK 持有；前台恢复不清空会话、草稿、聊天列表，也不主动退出登录。应用内和后台恢复使用现有顶部状态，不弹居中加载框。iOS 系统挂起仍可能导致心跳或本地转发暂停，本模块不能保证后台永久在线。

## 恢复顺序

1. 后台暂停应用层唤醒、健康检查与自动切线，废弃未完成检测的发布权限。原生 SDK 继续接收后台状态通知；不因为退后台主动关闭 OpenIM 或游戏盾。
2. 回前台立即尝试现有连接，并重新读取系统网络快照。快照最多等待 2 秒，不阻塞已有连接唤醒；空快照表示未知，不等同断网。旧快照不能覆盖新网络通知。明确无网络时暂停应用层重试，收到恢复通知或前台新快照后继续。
3. `IMNativeConnectionWake` 串行发送原生请求。只有已确认连接失败才请求 `networkStatusChanged`；健康连接只发送前台通知、取得服务端确认并触发增量同步。慢响应本身不触发强制断开。
4. 旧的后台前请求即使稍后成功，也不能代替新一轮前台通知、不能触发当前会话的补同步。原生调用仍占用一个请求槽，新一轮等待其释放，避免并发冲击 SDK。
5. 前台通知成功后不再固定 3 秒重复发送同样的通知。真实连接异常、同步失败仍按现有 3 秒应用层检查触发恢复；健康状态每分钟只检查失败标志，原生心跳/重连参数不变。
6. 路由检测由 `AutomaticNodeRuntime` 处理：当前线路健康时保留；换线之前必须通过三服务预检。处于游戏盾且所有线路暂时失败时，交给已有隧道和 OpenIM 重试，不退出重登同一线路。节点失败退避仍为 2/4/8/15/30 秒，真实网络变化或回前台会重新检查。

## 所有权与平台

- `core/network/transport_state.dart` 统一规范化网络类型，忽略空结果、重复结果与顺序差异。系统网络类型只是提示，不能证明业务服务可用。
- IM 恢复、API 检测均由登录会话持有；账号替换、关闭、退后台后迟到结果不能触发补同步。自动选线同时校验三项账号凭据、当前线路及网络版本。
- iOS 插件每个 SDK 初始化周期只注册一次生命周期/Reachability；卸载 SDK 时取消监听和待执行检测。初始快照、重复状态、断网通知不直接关闭连接；实际在线网络变化合并 350ms 后处理。Dart 与原生的同一路径重连信号在 1 秒内合并，不同路径不等待。
- 原生前后台通知仍保留，Android 继续使用已有 Activity 生命周期和经过网络验证的默认网络监听。共享 Dart 优化同时作用于 Android/iOS。

## 验证

测试位于 `test/core/network/`、`test/core/session/connection/`、`test/core/server_nodes/automatic_node_runtime_test.dart`，涵盖重复通知、无网暂停、丢失恢复通知、旧请求确认、后台中检测、账号更新、同线路保护与正常切线。

macOS 可运行 `sh ios/tests/Connectivity/run.sh` 验证原生网络路径策略；完整 iOS 编译与真机息屏/切网仍需要 Xcode/iPhone。不要将 Flutter 测试或 Swift 语法检查视为真机验证。
