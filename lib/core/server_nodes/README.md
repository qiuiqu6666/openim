# 启动节点选择

`StartupNodeSelection.prepare` 在 `Config.init` 中完成本地配置加载后、HTTP 客户端和 OpenIM SDK 初始化前执行。每次进程启动重新检查，后台恢复、页面切换、聊天和通话期间不切换节点。

域名节点优先，备用节点为 `129.226.192.93` 的 Chat `10008`、OpenIM API `10002` 和 WebSocket `10001`。三个地址作为一个整体保存。以前保存的 IP 地址不再被 Config 自动改回域名。

两个节点并行检测，每个节点整体最多等待 3 秒。Chat 使用现有公共平台接口；OpenIM API 使用无 token 的只读请求并确认缺少 token 的标准响应；WebSocket 网关确认其未鉴权参数响应。检测不发送账号凭据、不创建用户连接，不代替 SDK 的实际鉴权登录。重定向、超时、异常响应和任一服务不可达均视为该节点不可用。

全部不可用时保留上次配置和登录凭据，不阻止 App 继续启动。自定义服务器只检测自身，不回退到生产节点。现有节点页面复用该目录的地址模型和启动检测结果，手动测速沿用当前 Chat 公共接口检测。

测试位于 `test/core/server_nodes/`，覆盖完整节点检测、超时、域名恢复、备用选择、离线、配置持久化和自定义服务器隔离。
