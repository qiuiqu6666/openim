# 节点选择与自动恢复

节点01：业务 https://99chatapi.99chat.vip，IM API https://99imapi.99chat.vip，WebSocket wss://websocket.99chat.vip；客服 http://lhins-14l2mj2j.3w3hbb07j0xz.eo.dnse5.com:8815。

节点02：主机 lhins-14l2mj2j.3w3hbb07j0xz.eo.dnse5.com，业务 HTTP 10008、IM API HTTP 10002、WebSocket WS 10001；客服 HTTP 8815。客服可选，不参与可用性判断。2026-10-14 本机探测两条线路三项服务正常；客服 HTTPS 8815 报 TLS 协议错误，HTTP 正常。

StartupNodeSelection 在 HTTP 和 SDK 初始化前选择线路。TimedNodeProbe 并行进行无账号凭据的三服务检测；累计 1000ms 优先采用首选线路、1250ms 采用已验证备用线路、2250ms 收束探测。这是决策时限，不包含故障发现、SDK 重登或隧道准备时间。

AutomaticNodeRuntime 由应用绑定持有，前台登录会话响应 SDK 连接异常与系统网络变化，正常时每 30 秒检查。静默故障可能等待周期检测。无系统网络时暂停；失败按 2/4/8/15/30 秒自动重试。

自动和手动切换共用 ManualNodeSwitchService 的锁、账号校验、三服务预检与失败回退。ManualNodeSwitchRuntime 复用现有 SDK 会话所有者，重新初始化并登录，不清理账号凭据、不重放业务写请求。通话繁忙时延后切换。客服监听路由变化后重新连接。

没有可用直连且启用游戏盾时，启动原生 SDK，验证转发后的三项业务服务，再安装进程内路由；启动失败自动重试。游戏盾地址不写入偏好。自定义部署不回退到生产线路。

游戏盾只作兜底：前台每轮完整检测两条直连，同一条直连三项服务连续三次通过（样本至少间隔 30 秒）后主动切回，优先节点01。通常约 1～2 分钟确认恢复，通话繁忙时延后；网络、生命周期或账号变化清除连续成功记录。切回复用串行重连和失败回退，失败后暂停主动切回 10 分钟；游戏盾自身失效时仍立即走故障恢复。运行时恢复要求已有账号凭据；未登录页依赖启动选择。iOS 后台受系统挂起限制。切回直连后不关闭原生游戏盾实例，保留再次兜底能力，但应用业务路由已恢复直连。

测试位于 test/core/server_nodes、test/core/youmeng 和客服测试目录。真实设备仍需验证发送中切线、跨网络、息屏与登录态恢复；不能保证通话无中断。

冷启动现在读取 RouteHistory 的上次成功线路：直连优先验证上次使用的直连；游戏盾立即启动并行探测直连，直连结果不抢占本次启动路由，后续按恢复策略切回。历史仅在同步/重连成功时记录，不因一次健康探测或失败尝试覆盖。原生初始化的两个调度请求已并行，细节见 ../youmeng/README.md。
