节点01：业务 https://99chatapi.99chat.vip，IM API https://99imapi.99chat.vip，WebSocket wss://websocket.99chat.vip；客服 http://lhins-14l2mj2j.3w3hbb07j0xz.eo.dnse5.com:8815。

节点02：主机 lhins-14l2mj2j.3w3hbb07j0xz.eo.dnse5.com，业务 HTTP 10008、IM API HTTP 10002、WebSocket WS 10001；客服 HTTP 8815。客服可选，不参与可用性判断。2026-10-14 本机探测两条线路三项服务正常；客服 HTTPS 8815 报 TLS 协议错误，HTTP 正常。

本地存储和 HTTP 客户端先初始化，正常 ChatApp 只挂载一次。startup/StartupNetworkPreparation 在首帧后、首次 SDK 初始化前选择线路，就绪后更新 HTTP 地址并放行 SDK。TimedNodeProbe 并行进行无账号凭据的三服务检测；累计 1000ms 优先采用首选线路、1250ms 采用已验证备用线路、2250ms 收束探测。这是决策时限，不包含故障发现、SDK 重登或隧道准备时间。

2026-10-15：HTTP 检测统一使用 `public_health_check.dart`，分别请求候选 `chatApi/healthz` 和 `imApi/healthz`，严格验证 HTTP 200、JSON 对象、`status:ok` 及对应 `chat-api`/`openim-api` 标识。删除故意无 token 请求 `/user/get_users_info` 的线路探测，不修改原生 SDK 真实资料查询的接口或凭证传递。手动测速仅测 Chat HTTP，改用同一健康检查；平台配置的正常业务读取仍使用 `/chat/platform`。

健康请求使用独立客户端，清除鉴权拦截器、预置请求头及查询参数，不携带 token、Authorization 或登录 Cookie；禁止自动重定向，保留默认 TLS 验证。诊断头为 `operationID:line-probe-<UUID>`、`X-Client-Source:line-probe`，可获得实际安装包信息时附加 `X-Client-Version:<version>+<build>`，不硬编码版本。原有独立网关可达性预检仍保留，HTTP 健康成功不等于网关连接、业务 RPC、登录或消息同步成功，不产生这些成功事件。

`NodeAvailabilityProbe` 的同一实例、同一候选和模式共享在途任务；自动切线及 API 连接检查持有各自的检测器，在网络、线路、后台或销毁时取消过期请求，SDK 注销关闭对应 API 检查器。手动测速同样取消旧网络/线路及后台结果。启动决策完成即取消未决候选；保留原有总超时（常规 2.25/3 秒、手动 8 秒、游戏盾预检 15 秒），失败退避加入最多 250ms 的随机提前量且保持原上限，不回退至无凭据业务探测。

定位、验证及发布边界见 [健康探活修改验收](../../../docs/line-probe-health-validation.md)。

feedback/ 明确区分 startup 和 reconnect，默认按静默重连处理。应用内自动切线、失败重试和后台恢复保留当前页面及交互，不调用居中加载弹窗，连接情况由现有顶部连接状态展示。冷启动连续等待超过 1.2 秒才复用视频保存的 EasyLoading 组件，始终只显示“正在连接…”，不因检测、游戏盾握手、退避重试阶段变化而更换文案、尺寸或重启动画。短时间成功则完全不显示。

准备失败只重试网络，保留本地存储、路由、账号凭据与绑定，不再 runApp 独立错误页。首次路线就绪前暂停运行时自动切线，避免与启动选择竞争。弹窗按操作归属关闭，不覆盖或关闭保存视频等其他功能的反馈；进入后台取消延迟显示并隐藏，回前台重新经过延迟，只在冷启动仍未完成时显示。自动重连不会重新展示启动弹窗。网络提示不拦截页面操作，不显示伪造进度或成功状态。

AutomaticNodeRuntime 由应用绑定持有，前台登录会话响应 SDK 连接异常与系统网络变化，正常时每 30 秒检查。静默故障可能等待周期检测。无系统网络时暂停；失败按 2/4/8/15/30 秒自动重试。

重复网络快照与连续 connecting/failed 回调不会反复重置失败退避；真实网络变化和前台恢复即使发生在测速中，也会在旧检查结束后立即补一次新检查。旧网络、旧凭据或旧线路的结果不能切线。当前已经使用游戏盾时，短暂探测失败不会退出重登同一个节点。前后台恢复与原生通知所有权见 ../session/connection/README.md。

自动和手动切换共用 ManualNodeSwitchService 的锁、账号校验、三服务预检与失败回退。ManualNodeSwitchRuntime 复用现有 SDK 会话所有者，重新初始化并登录，不清理账号凭据、不重放业务写请求。通话繁忙时延后切换。客服监听路由变化后重新连接。

没有可用直连且启用游戏盾时，启动原生 SDK，验证转发后的三项业务服务，再安装进程内路由；启动失败自动重试。游戏盾地址不写入偏好。自定义部署不回退到生产线路。

游戏盾只作兜底：前台每轮完整检测两条直连，同一条直连三项服务连续三次通过（样本至少间隔 30 秒）后主动切回，优先节点01。通常约 1～2 分钟确认恢复，通话繁忙时延后；网络、生命周期或账号变化清除连续成功记录。切回复用串行重连和失败回退，失败后暂停主动切回 10 分钟；游戏盾自身失效时仍立即走故障恢复。运行时恢复要求已有账号凭据；未登录页依赖启动选择。iOS 后台受系统挂起限制。切回直连后不关闭原生游戏盾实例，保留再次兜底能力，但应用业务路由已恢复直连。

测试位于 test/core/server_nodes、test/core/youmeng 和客服测试目录。真实设备仍需验证发送中切线、跨网络、息屏与登录态恢复；不能保证通话无中断。

冷启动现在读取 RouteHistory 的上次成功线路：直连优先验证上次使用的直连；游戏盾立即启动并行探测直连，直连结果不抢占本次启动路由，后续按恢复策略切回。历史仅在同步/重连成功时记录，不因一次健康探测或失败尝试覆盖。原生初始化的两个调度请求已并行，细节见 ../youmeng/README.md。
