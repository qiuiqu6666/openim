# 三公授权与路由恢复

- `sangong_access_policy.dart` 区分账号特权与群代理授权。
- `sangong_operation_scope.dart` 固定单次请求的账号、群、租户、权限版本，旧请求不能跨版本继续使用。
- `sangong_route_revalidation.dart` 负责已打开运营页面的只读重新授权。能力缓存失效或群配置重新查询时保留路由，重新确认同账号、同群、同租户及运营权限后建立新页面范围。

路由恢复由现有 `SangongPrivilegeRouteGuard` 执行，供 `SangongPageRoute`、管理主页、截止预览和本局结算弹层复用。等待期间停用原业务内容；成功后重新创建内容，避免旧异步结果或表单跨权限版本使用。网络失败留在当前路由重试，账号退出、离群、确认撤权或租户改变则只移除对应路由。

恢复不执行写操作。截止和结算恢复时必须重新读取同一局数据，局号改变就结束原弹层；冲正及其他命令确认仍保留原范围限制，不自动恢复或重发命令。连续失效最多重读三次，避免请求循环。普通聊天不参与此路由保护。

回归测试：`test/pages/group_features/sangong/authorization/route_revalidation/`，覆盖真实群缓存、运行时、侧边入口、嵌套路由、网络失败及权限变化。

2026-10-11 补齐代理侧“查、团、个”：独立代理大厅入口与 `agent: true` 的子路由也走重新校验。代理恢复严格验证原账号、群、厅和新的 `canOpenAgent`，不要求代理拥有运营账号特权；缓存失效时仅保留加载中的路由，不开放旧页面或旧请求。明确撤权、换厅及退出仍关闭对应私有路由。

`agents/halls/sangong_agent_hall_binding.dart` 将固定厅运行时的生命周期放到外层路由，刷新重建大厅页面时保留同一个运行时，并同步最新群上下文，防止下级详情因父页面刷新被连带关闭。离开外层路由后统一销毁。测试新增代理三入口的亮暗主题恢复、嵌套页面、网络重试、换厅、撤权和退出；校验过程只发读请求，不重放划转/返水命令。

## 内部页面巡检（2026-10-11）

| 范围 | 刷新策略 |
| --- | --- |
| 管理首页、游戏规则、全部用户、用户详情、成员管理、代理群管理、报表中心与报表详情 | `SangongPageRoute` 运营恢复；保留路由，重新确认绑定并重建页面请求 |
| 我的配置、只有配置权限的管理入口 | 配置恢复独立检查 `canConfigure`；首次初始化还必须经绑定查询确认 `canInitialize`，群管理员身份本身不能授予已有群的配置权限 |
| 代理大厅、“查/团/个”、下级详情、划转记录 | 代理恢复；保持固定厅运行时，重新确认 `canOpenAgent` |
| 截止预览、本局结算 | 恢复后重新读取同一局；局号改变关闭旧弹层 |
| 用户资料内游戏流水弹层 | 运营恢复，同时校验资料目标及父页面运行时，切换用户/账号时关闭旧弹层 |
| 群选择公共弹层、未授权说明 | 仅公开状态，不因能力缓存刷新退出；账号/资料目标变化关闭旧作用域，即使首次鉴权尚未完成 |
| 写操作确认、金额输入、配置目录选择 | 不恢复旧确认和旧选择；能力/租户变化只取消当前弹窗或选择页，底下的业务页单独恢复；代理确认支持真实个人代理授权 |

三公内部的页面入口、资料弹层及共享确认流程已按上述边界核对。`recoverOnRefresh: false` 专用于捕获旧表单上下文的选择页，避免重建后返回结果给已失效的调用者。此检查不自动重发写请求，也不承诺保留旧权限版本下未提交的表单。

新增 `related_pages_revalidation_test.dart` 覆盖实际内部页面的亮暗主题刷新、仅配置权限、配置撤权、代理确认与输入、选择页取消。账本入口测试覆盖真实资料页刷新与账号切换；共享测试宿主初始化提示组件，路由确认测试使用当前的确认组件。

同时修复游戏流水失败重试的状态更新：先创建异步读取，再同步替换 Future，避免 `setState` 回调返回 Future 导致重试异常。此次页面、资料流水、配置保存、代理管理和报表范围的回归共 253 项通过，三公模块及新增/修改测试的静态检查无问题。设备端实际网络联调仍需真机验收。
