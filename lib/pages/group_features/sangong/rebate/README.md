# 返水入账凭据

用户申请返水和关机自动返水沿用已有资金入账，只在同一事务中保存该笔账变的固定凭据：流水、当时比例、实际金额、申请/自动方式及用户/代理类型。查询 `user-report` 和 `ledger` 均返回可选 `rebate`，客户端不会用当前用户配置推算旧比例。

用户详情“上下分”列入用户返水、代理返水及返水冲正，人工上分/下分统计保持原口径，另列返水净入账。报表中心账变复用同一凭据组件。代理显示团队累计流水和本人配置比例，并注明按各分支差额计算。没有凭据的旧记录仍显示真实入账金额，缺失流水和比例显示未记录。

`models` 解析冻结值，`widgets` 展示凭据；查询/权限/分页仍由既有 Sangong 接口及报表控制器负责。新凭据不会再次入账，也不会改变历史余额。

修改返水比例不发放返水。未结流水保留，之后按新比例计算，改为 0 也不清除；已结记录不回算。旧 claimType=RATE_CHANGE 凭据仍按历史原值显示“修改比例前结清返水”，新修改不创建此类付款。

管理员 agent.attach 支持首次绑定及换绑，整支下属团队一起移动；未结流水转入新关系（含牌局已结但返水尚未领取的流水），各层已结部分保留。客户端只提交当前租户数字 userId，不计算或补发历史返水。代理入口禁止修改上级。确认成功后刷新成员资料，并通知已加载的团队/待领统计重新读取服务端；超时复用相同参数的 requestId，业务错误不自动重试。
