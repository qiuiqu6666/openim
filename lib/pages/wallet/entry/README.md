# 钱包入口

`WalletEntryCoordinator` 统一处理首页底部钱包与“我的”中的钱包入口，在切换标签前检查支付密码；首页只提供选择标签的回调，不持有支付密码或缓存密码状态。

复用 `OpenIMProfileService` 和 `TradePasswordPage`：`GET /chat/fund/pay-password` 读取 `data.set`，未设置时用根导航打开现有设置页；设置页 `PUT` 成功并返回 `true` 后重新查询状态，确认生效才进入钱包。取消、请求失败或响应缺少布尔状态时保留原标签，错误沿用公共居中提示。每次点击重新查询，不以本地缓存代替后端状态。

协调器由首页创建与释放；重复点击共用当前检查，选择其他标签取消待完成导航。请求同时归属原标签、路由、登录账号、服务地址和 token，响应时仍在后台、已退出登录、已切换账号或已关闭页面的请求不能打开设置页或钱包。设置页服务同时检查原会话，防止在旧页面输入密码时误用新账号的 token。钱包交易操作原有的密码检查保持独立。

本地 99chat 的 `lib/src/pages/home_page.dart` 与 `lib/src/pages/wallet/wallet_pay_pin_guard.dart` 为入口和密码流程参考；参考仓库在交易前检查密码，此处按用户要求提前到钱包入口。没有新增设置页面或后端接口；沿用现有页面的亮暗主题。

对应测试位于 `test/pages/wallet/entry/`。

验证（2026-10-06）：入口协调、真实首页两入口、亮暗主题、根导航、PIN 设置与返回、取消与重复点击、会话和生命周期、五种语言提示、真实状态接口响应契约共 33 项测试通过；已有设置页、安全接口、反馈、首页会话和玻璃导航 34 项回归通过。修改范围与测试目录 analyze 通过，Android debug APK 构建成功。未进行线上密码写入或真机安装验证。
