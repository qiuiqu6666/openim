# 闪兑

旧 `wallet_exchange_screen.dart` 保留兼容导出；本目录维护三币兑换页面、报价状态与表单组件，使用 `WalletFundApi` 的真实余额、`POST /chat/fund/swap-quotes`、`POST /chat/fund/swaps` 以及订单恢复接口。

USDT、TRX、BI99 支持六个方向。金额使用 `FundAmount` 精确解析，接口发送 BI99；输入后获取服务端报价，主界面展示 `estimatedReceived` 和 `inputValueUsd`。未知美元估值保持 `--`。展示数量使用现有两位小数格式器，实际输入与提交仍保持 USDT/TRX 六位、BI99 两位精度。不依赖旧 `WalletMe` 汇率、不做本地余额加减、不构造历史列表。

页面拥有操作协调器；重复支付回调、未确认提交、关闭及账号切换由共享操作模块保护。付款前复用原支付密码状态和设置页面，确认支付仍使用 `PayAuthHelper`。测试位于 `test/pages/wallet/operations/`，实际页面预览使用可选 `WALLET_OPERATIONS_PREVIEW_DIR`，仅连接测试 API。

## 数字键盘布局

按用户提供的截图改为白底、大号输入金额、双币卡片、预览和常驻数字键盘。根据后续要求移除整个顶部买入/卖出/闪兑分段及记录图标，保留系统返回按钮。对照了本地 `reference-99chat/lib/src/pages/wallet/wallet_exchange_screen.dart`，实际样式以用户截图和后续要求为准。不新增 USDC。数字键盘复用 `WalletAmount.clean` 的输入精度规则，确认前仍由 `FundAmount` 精确解析与校验余额。支付 PIN 键盘保持原实现。

币种整行可以打开原币种下拉选择，交换和切换币种清空输入及旧报价；已有交易草稿时禁止改动。交易状态卡保留已知订单查询，闪兑提交超时但没有服务端单号时使用原业务单号恢复。颜色、图标、币种图片、返回路由和支付弹层继续复用现有钱包能力，新布局组件和尺寸颜色集中在本目录，提现及其他已对接页面保持原流程。

`WalletExchangeLayout` 在常规手机上固定预览按钮和数字键盘，上部金额、币种和交易状态可以滚动；矮屏或大字体切换为整页滚动。金额和币种单位分开排版，数值保持可读的最小字号，超长时横向滚动并跟随输入末位，显示“左右滑动查看完整数量”，不截断实际输入。交换按钮归属独立分隔层，保持 48 像素点击区域；窄屏卡片的数量单独换行。超出真实可用余额时显示纠错提示，预览仍由原精确金额校验控制。

## 报价与交易恢复

- `data/wallet_swap_quote.dart` 使用整数验证服务端十八位汇率及向下截断后的实得，校验方向、数量、估值、价格调整和 Unix 毫秒有效期。
- `data/wallet_swap_quote_controller.dart` 对输入采用 350 毫秒合并请求。输入改变立即使旧报价失效，过时或其他账号响应不会回写。按服务端绝对有效期判断到期，暂停时取消请求计时、退出时取消监听；到期不在后台自动报价。
- `widgets/wallet_swap_quote_sheet.dart` 展示转出与预计实得，用户确认之后复用原支付密码流程。支付时再次检查有效期；本地到期或服务端返回 20072/20074 会关闭此次支付，要求重新展示报价并确认，不静默换价。
- 新页面提交始终带已确认的 `quoteID`。草稿在 POST 前持久化原 `clientOrderID`、精确输入、目标币、报价编号和预估实得，不保存密码。密码错误重试保持原参数；明确拒绝后重新预览可以开始新交易。
- 超时、内部服务错误、20062 或 20073 保留原草稿。优先按已知 `orderID` 查询，否则使用 `GET /chat/fund/orders/by-client` 的编码查询参数。恢复核对原业务单号、币种、数量、目标币、报价和实得。
- 查询 20032 仍不证明原提交未成交，不清理草稿、不自动 POST 或换业务单号。当前页面仅提供查询恢复与客服入口，延续原防重复策略；旧版无报价草稿保持查询兼容。

## 成功后继续操作

仅当订单已验证为 `swap + done` 且成功、终态时，页面重存已验证终态标记后清理交易草稿、输入和报价，并查询真实余额。下一笔仍须由用户输入、预览确认和支付才能提交；不会沿用上一笔业务单号或报价。迟到成功及旧终态草稿重开复用同一流程，重开时先查询服务端确认成功。未确认、查询失败或未结束的订单保持原参数锁定。

按用户最新要求，成功后只显示提示，密码弹窗键盘区域切换为支付成功后关闭，页面不展示成功详情卡或订单按钮。清理持久化失败时保留原草稿，提示已成功但恢复输入失败，固定按钮显示“继续闪兑”供重试恢复输入，不重复提交。页面文件超过 500 行已复核职责：只协调生命周期、输入、报价、支付和成功恢复；支付 UI、报价状态和交易持久化仍分别归属独立文件，未扩展共享交易协调器或其他已对接页面。

管理员价格配置在后台完成。移动页面不调用 `/fund/swap-config`，也不请求 OKX；所有价格和估值来自当前用户的服务端报价。测试价格仅存在测试和预览中。
