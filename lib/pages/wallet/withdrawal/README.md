# 链上提现

链上提现入口选币后直接进入 `form/WalletChainWithdrawalScreen`：地址、网络、数量、可用余额、到账本金、网络手续费与总扣款在同一滚动页面，提交复用现有支付密码流程。结构按用户提供的提现参考图调整；对照 99chat 的地址、金额和确认页后复用其钱包颜色、间距、字体与导航。旧 `WithdrawAddressScreen(initialTargetKind: chain)` 委托新页，跳过旧好友和钱包地址请求；旧金额与确认页保留兼容，好友内部转账仍进入现有 FundSendPage。

`form/` 的页面负责生命周期和导航，控制器负责账户隔离、原单恢复及只读校验，`widgets/` 负责表单、费用摘要和网络选择。需要新组件是因为既有链上页面分属三步，没有同页组合与可编辑表单；不新建资金写入链路。复用 WalletOperationCoordinator、WalletWithdrawalPolicy、WalletOperationStatusCard、WalletQrScannerPage、钱包提现记录和支付密码设置/输入组件。

正式数据来自 `GET /chat/fund/balances` 与 `GET /chat/fund/deposit-address`。仅提供接口实际支持的 USDT/TRX、TRON；没有域名解析、链上地址簿或实名认证额度数据，地址栏提供真实粘贴/扫码。按最新用户要求移除页面的“链上提现说明”卡片，网络提示仅保留在网络选择和说明弹窗中。支持亮暗主题和五种语言。

`widgets/wallet_chain_withdrawal_info_dialog.dart` 负责短说明的内容高度、宽度上限及可滚动大字布局，地址、网络、数量和手续费说明均使用具体标题和单个“我知道了”按钮。复用钱包颜色和布局 token，以及 Flutter Dialog 的遮罩、返回与焦点机制。既有 CustomDialog 是两按钮确认且没有正文展示，AppDialog 使用 Get 全局上下文和 Cupertino 样式，因此本页面的单按钮说明保留独立实现。

表单在激活和前台恢复时串行刷新，被其他页面覆盖或进入后台时停止接受迟到数据；自有扫码和网络选择返回保持输入。只读说明弹窗保持父页读取状态，关闭“我知道了”不触发重复刷新；父页是否当前的提交门槛保持独立。加载条使用不参与内容布局的覆盖层，刷新时保持表单几何和滚动位置。提交前重新校验地址校验和、自地址、最低额、同币种费用、6 位精度和含费用的 int64 范围。设置支付密码返回后再次读取余额与规则，确认父页仍当前才显示 PIN。业务金额均以整数最小单位计算，到账本金与另收手续费分别显示，“全部”为可用余额减手续费。

`GET /chat/fund/deposit-address` 返回的 `currencyRules` 同时提供充值和提现规则。金额输入页的独立 `amount_entry/` 控制器在激活和恢复时读取当前规则，不轮询地址分配；显示真实最低提现、同币种固定手续费和本金加手续费的总扣款。100% 按余额减手续费计算，百分比与金额使用整数最小单位。未知规则不会按零手续费处理。

确认页先恢复原交易；新提交前重新请求余额和规则，校验最低提现及可用余额能否覆盖本金和手续费。缺失最低金额、手续费或手续费币种时阻止新提交并提供重试。旧已提交/待确认订单查询不依赖新配置，收据返回的费用覆盖展示中的规则费用。规则、金额及提示支持简体、繁体、英语、日语、韩语。

链上提现先保存不可变业务单号、数量与地址，再通过资金安全模块检查等待期、设备与短信要求；本次验证码仅保存在内存，支付密码和短信验证码都不进入草稿。预检查、发短信与提交使用相同 `mode=chain/network=TRON` 参数。

链上提现密码弹窗顶部显示本金加同币种手续费的总扣款金额，与钱包付款摘要一致；安全验证与提现接口的 `amount` 仍为到账本金，由服务端另收手续费。金额相加复用现有 `WalletWithdrawalPolicy.totalDebit` 的精确整数计算，主入口与旧确认入口共用该规则。

失败结果复用 `WalletTip → IMViews.showToast` 简短居中提示，不在表单中显示结果卡、业务单号或“新交易”。主链上提现表单成功受理后打开 `WalletWithdrawalSuccessScreen` 全屏结果页，按实际订单状态说明等待审核或已登记出款，点击完成或返回回到表单。密码弹窗内失败重试仍保留同一笔参数；弹窗关闭后，取消或明确拒绝的未提交草稿可释放并继续编辑，主页面保留输入。已确认受理的提现由服务端历史记录继续跟踪，释放本地本次操作；主链上提现表单清空地址和金额，保留 TRON 网络选项。`finishWithdrawalInteraction` 只释放未提交草稿或匹配真实确认订单的标记，锁住并发操作；未知写入、清理失败或原单不一致时保留草稿及查询入口。

当前交易短信接口仅有安全预检查和发送验证码。短信弹层的“继续支付”检查六位格式和期限后进入密码弹窗，验证码与支付密码一并由资金提交事务验证；未调用支付密码重置接口或虚构独立短信验证接口。

`withdraw_pending/withdraw_approved/withdraw_done/withdraw_failed` 分别显示等待审核、等待出款、已登记出款和退回。完成只代表管理员登记实际出款，不视作自动广播或链上自动确认。订单详情展示服务端真实哈希、转出/提现地址和审核/出款说明，哈希可打开 TRONSCAN。无服务端订单号的超时提交按原 `clientOrderID` 查询；未找到仍保留原参数，不自动再次 POST。

付款前复用既有支付密码查询/设置能力；本模块不改变其服务和页面。新页面及控制器测试位于 `test/pages/wallet/withdrawal/form/`，兼容支付测试位于 `test/pages/wallet/operations/`。设置 `EXPORT_CHAIN_WITHDRAWAL_PREVIEWS=true` 运行新页预览测试可导出真实 Flutter Widget 的亮暗、小屏大字、横屏、键盘遮挡和网络弹层截图到 `.temp/chain-withdrawal-reference/`，全部使用本地夹具且不会提交真实交易。

规则测试按 `test/pages/wallet/withdrawal/` 与 `test/pages/wallet/data/currency_rules/` 归属。规则模型和精度运算位于 `../data/currency_rules/`，跨页面语言格式位于 `../widgets/currency_rules/`。

既有 `../withdraw_transfer_confirm_screen.dart` 的长键盘/地址视图保留，本次新增规则职责均抽入独立模块；兼容入口仅负责生命周期、草稿及页面组合，未连带重构好友转账或旧键盘布局。
