# 会话未读计数与跨设备校准

主页消息、群聊标签共用 `conversation_unread_count.dart` 的通知计数规则，参考 99Chat `ConversationUnreadAggregate`：排除免打扰、拒收和归档会话。免打扰会话本身仍保留 SDK 的真实未读、列表小红点与文件夹计数。

SDK 全局总数与界面分区数字不同。校准使用独立的 SDK 汇总口径（`recvMsgOpt < 2` 且最新消息时间大于零，包含归档及所有 SDK 类型）；这个比较只决定是否重新读取 SDK，不用于清零或分配会话未读。

`ConversationUnreadSync` 由 `ConversationLogic` 持有，订阅现有总未读事件。220ms 合并窗口内先应用会话变更，仍失配才调用原 SDK 分页读取。普通会话变更已对齐时不追加查询；重复同数事件不触发查询循环。正在读取时延后到快照完成，失败保留原列表，不自动循环重试。回到前台、真实重连时会合并一次校准，以补偿后台漏接的更新；列表初次读取失败仍复用既有恢复流程。

校准沿用原账号、token、读取代次、删除与群身份保护，并合并读取期间的增量。校准意图保留到最新读取成功应用，普通刷新抢占旧请求时不会丢掉意图，登录缓存也不能代替新 SDK 校准。仅未在读取期间更新的会话，才允许 SDK 同一消息目标的零未读覆盖旧本地已读投影；新的消息 ID、序号与读取期间收到的新消息仍保持原有保护。若期间变更留下残余失配，每个外部信号最多补读一次；再次失配则等待新信号，避免无限刷新。总数零不能直接清空所有群聊，静音群也可能不在这个总数中。

清空列表时重置校准代次；关闭控制器时取消定时器与现有订阅。校准沿用原 SDK 列表请求，客户端没有新增已读写入或后台轮询。服务端/原生 SDK 仍须同步跨设备的已读状态；没有收到更新且 SDK 本地数据未变化时，界面不能证明远端已读成功。

测试入口：`test/pages/conversation/unread/`、`test/pages/home/home_unread_badge_test.dart`、`test/pages/conversation/reads/`，以及原会话启动、刷新生命周期和批量编辑回归。
