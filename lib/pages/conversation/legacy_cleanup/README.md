# 旧服务账号私聊清理补偿

本模块仅补偿 `legacy-official-contact-removal-20261010-v1`，服务器为 `129.226.192.93`，截止时间为 `1791582008267` 毫秒。只处理涉及源码中两个精确旧服务 UID 的单聊，不按昵称匹配，不处理群聊，不成为永久屏蔽规则。

当前 Android SDK core `v3.8.3-patch.12` 的会话增量同步使用 `skipDeletion=true`；1703 通知只清空消息、不清会话排序时间。因此首次加载、SDK 同步完成和下拉刷新时，本模块先读取全部本地分页，再通过现有 `/conversation/get_full_conversation_ids` 确认服务器已删除目标 CID。删除前再查询一次服务器，并复读本地会话；截止时间之后的新消息、草稿、无确定时间的草稿和未发送消息都会阻止清理。

模块冻结 SDK 分页返回的可见历史消息快照，仅对已发送、序号大于零且时间不晚于截止时间的消息，按 clientMsgID 调用 `deleteMessageFromLocalStorage`。消息级 SDK 删除回调同步移除应用消息缓存；删除完成后再检查服务器和最新本地状态，最后调用纯本地 `hideConversation` 重置会话。服务端通过持久化 2102 通知按备份中的精确旧 seq 补偿离线设备。不会调用会写服务器的 clear/delete-conversation API，不影响后来新消息的服务器历史。

成功后清理页面缓存及草稿，按服务器、owner、epoch、CID 保存完成标记。错误不隐藏会话、不写成功标记，之后可重试。账号、凭证、服务器和控制器生命周期变化会取消后续操作。SDK 消息删除是本地逻辑删除，不保证物理擦除设备数据库文件。

SDK 没有按截止状态原子隐藏会话的公开接口；重复读取能保护已观察到的新会话，但无法消除最后一次检查之后、新消息与本地 hide 同时发生的 UI 竞态。消息删除本身始终限定快照中的旧 clientMsgID，新的消息内容不会被该补偿删除。服务端清理须先完成并停止该次维护写入。旧版客户端需要更新才能完成会话列表补偿；未运行应用的离线设备无法被远程保证立即擦除。

测试位于 `test/pages/conversation/legacy_cleanup/`。没有新增页面或平台依赖，Android/iOS 均使用现有 SDK 接口；不改变亮暗主题。
