# 老用户补偿活动（正式客户端）

首页消息列表中的 CompensationHomeEntry 拥有入口请求、前台定时刷新、单次首页会话弹窗记录与导航。只有已发布活动显示横幅，有资格且未领取才自动弹窗。无活动和入口查询失败均隐藏入口，不阻塞聊天。活动详情始终重新请求，已领取结果独立于活动截止状态。

## 归属与复用
- data：复用 FundApi 的登录 token、节点地址、operationID 和错误处理；捕获账号与 token，拒绝跨账号响应。
- models：服务端字段校验，金额保持十进制字符串，不生成领取金额。
- state：领取互斥、服务端时间加 Stopwatch、截止禁领、超时查询恢复、钱包刷新信号。
- presentation：已确认的浅色红金预览及其 99 品牌素材；暗色主题使用独立语义色；大字金额移到插画外；规则滚动，底部按钮在安全区。用户要求不展示绝对截止日期与时区行，仅展示倒计时。
- 入账记录展示服务端确认的金额、领取时间和 receiptID；可进入现有 WalletRecordScreen 查看全部99币明细。使用现有 AppMaterialPageRoute 导航。
- 未修改消息 SDK、聊天数据链路、资金扣账算法。新增组件因为正式项目尚无补偿活动 UI；参考仓库没有对应活动模块，视觉依据是用户确认的独立预览。

## 接口
POST /chat/fund/compensation/entry、detail、claim。后两者只提交活动 id，无客户端金额、资格或余额。资金以服务端事务为准。

入口以服务端当前已发布活动为准：无活动时不弹窗、不显示横幅。界面验证不执行真实领取。

## 验证
测试位于 test/pages/fund/compensation；模拟数据仅存在测试中。视觉截图通过 compensation_visual_test 的显式环境参数导出，截图金额、时间均为测试数据。运行相关 flutter test、flutter analyze；构建 arm64 debug APK。首页现有回归测试有6项失败，在还原原始 conversation_view 后仍复现（连接状态测试替身/旧预期），非此次新增。
移动端检查脚本将 token 定义本身识别为硬编码颜色，属于误报；无活动入口隐藏是明确产品行为，错误/离线恢复在详情页提供。未执行真机领取或 iOS 构建。

钱包海报：WalletHomeView 在代币列表后复用 CompensationHomeEntry(poster: true)，关闭自动弹窗，仅点击跳转。活动总奖池来自服务端，空活动隐藏，随钱包Tab激活与前后台刷新。CompensationPoster 的图片仅装饰，文案使用可缩放文字组件。44 项相关状态/组件测试通过；钱包布局测试原有16项长金额断言失败，移除本次钱包改动后仍复现。2044 arm64 debug APK 已构建。

弹窗恢复独立 Demo 红金海报风格：compensation_invitation_template.png 为清除固定奖池金额后的装饰底图；所有金额均来自服务端。普通字号采用海报布局，大字号采用同配色可滚动布局，均保留 48dp 关闭入口。金额不再决定是否切换白色弹窗。

按用户最新要求，弹窗直接展示原始 compensation_cutout.png，不叠加任何可见文字、不按金额切换布局。原图自带300万宣传文案保持不变；真实金额、资格和领取结果仍由详情页接口决定。关闭按钮与原图按钮位置的透明点击区域保留。
弹窗跳转修复（2048）：首页被根弹窗覆盖后 active=false，pop 返回时该标志尚未恢复，原判断会吞掉点击。显式点击改用 mounted、前台和账号有效性检查；保留后台轮询 active 门控。回归测试先复现失败，修复后31项相关测试通过，静态检查和arm64构建通过。未真机验收。
2051详情视觉优化：独立CompensationHero统一四态，领取金额单独突出；倒计时与规则卡片分组；固定金额显示固定规则。保留服务端资格、领取和查询逻辑。35项相关测试通过，四态截图仅使用测试数据；静态检查与arm64构建通过。未真机验收。

详情页采用红金活动视觉，装饰背景与可访问的动态文字分离；继续复用现有红包素材、控制器、领取与钱包记录链路。剩余资金读取 activity.remainingAmount，兼容旧响应缺失字段时显示“暂未提供”，不从个人领取金额推算。页面说明点击展开完整规则；领取及截止时间明确使用 UTC+8。大字体时红包金额移到独立卡片，资金指标纵向排列，避免溢出。
