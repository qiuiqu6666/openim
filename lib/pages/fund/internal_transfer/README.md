# 内部提现表单

钱包首页的“提现 → 内部转账 → 选择币种”进入 `FundSendPage(internalWithdrawal: true, initialCurrency: ...)`，显示用户提供截图中的账号、数量、到账与零手续费布局。选币阶段继续使用既有钱包控制器；余额与付款使用当前登录用户的 `FundApi`，不使用截图中的模拟数值。USDT/TRX 保留六位、99币保留两位精度，“全部”只取可用余额，不加冻结余额。

- 默认账号类型为99号；用户选择列表按99号、邮箱、手机号排序，帮助说明保持一致。账号类型弹窗复用公共 `showAppActionSheet`，与设置的主题、语言选择保持同款圆角分组与独立取消按钮；标题、选项及当前选择标记覆盖五种语言，取消文案使用 Flutter 的 Cupertino 本地化。取消、遮罩和系统返回不修改账号类型或输入；选择其他类型沿用原表单清除收款账号的行为。手输帐号调用 `POST /chat/fund/recipients/resolve`，使用服务端确认的真实收款人，邮箱保留大小写；拒绝本人、官方账号及账户、令牌、服务器变化后的旧结果。生产解析不再依赖联系人模糊搜索或要求回包包含手机号。好友付款仍使用真实 IM userID，底层兼容 UID 精确解析以保留已有协议。
- 手机号输入前显示可点击区号，默认 `+86`，复用现有 `CountryCodePage` 选择国家/地区。区号改变保留号码、数量，清除已确认收款人并重新查询；号码和区号作为独立字段确认并随业务草稿冻结，取消选择不改变草稿。未确认付款前不创建资金订单。
- `presentation/fund_transfer_friend_picker.dart` 使用 SDK 好友分页、现有头像/搜索组件及资料解析器，排除自己、黑名单和官方账号；公开账号缺失时仅展示好友摘要，付款始终使用真实 IM ID。好友搜索范围为已加载的昵称、备注与已知公开账号。
- `data/fund_transfer_recipient_policy.dart` 复用既有官方身份解析，屏蔽 99Message、99Pay、assistant 和 `accountType: official` 资料。列表、点选和收款人解析均应用该策略；普通同名好友仍可正常选择，无额外资料请求。
- `presentation/fund_transfer_friend_picker_tokens.dart` 将选择页底色与提现表单表面统一，保持搜索框层级、分割线、亮暗文字对比度和钱包色操作反馈；搜索、清除、光标、选区及加载/重试颜色显式使用该配色。
- `presentation/fund_internal_transfer_form.dart` 与 tokens 负责布局、输入、帮助/历史入口、可用余额、到账金额和按钮，支持日夜主题、窄屏、大字体、键盘及横屏。`fund_internal_transfer_actions.dart` 集中维护账号类型选择、说明和现有历史页入口。
- 表单标题按整页中轴居中，两侧分别保留同宽操作区域；返回、说明和历史仍保留48px点击范围。大字体时标题自然换行并增加栏高，避免被两个右侧操作按钮挤偏或截断。

页面结构按本次截图调整；已有接收人/链上入口已对照 `reference-99chat/lib/src/pages/wallet/withdraw_address_screen.dart`。本次新增账号表单与单选好友页，是因为既有地址页混合链上地址/好友列表，群收款人选择器只接受群成员，均不适合此入口。继续复用 AvatarView、SearchBox、AppBackButton、FundPageColors、密码支付弹窗和现有转账 API。

付款协调仍由现有 `FundSendPage` 持有，保留支付密码设置、固定付款草稿、账号隔离的持久化订单、失败重试与确认成功状态，避免为钱包入口建立另一套付款所有者。该既有长文件只负责接入新表单和收款人解析；新布局、搜索数据、好友页、类型/帮助/历史界面均已拆分到本目录。其他红包/聊天转账入口保持默认分支，后续若拆分付款协调应覆盖全部既有订单恢复测试，不以 part/共享私有状态模拟拆分。

内部表单支付币种固定为所选币种；继续调用 `POST /chat/fund/transfers`，场景为 `internal`，提交真实 `recvID` 及已确认的账号描述。先执行安全预检查和必要的本笔短信验证，再显示原密码支付弹窗；成功后直接到账，钱包余额和历史记录收到刷新事件。收款人变更清除此前解析；未确认付款按实际收款人恢复原币种、金额和订单 ID，并先通过 `/chat/fund/orders/by-client` 查询原结果，已成功则不再发短信或提交付款。账号输入的键盘“下一项”可先确认收款人，因此当前可用余额已被原付款扣除到零时，也能恢复并确认原交易。支付密码、短信验证码及 challenge 均不保存到待确认交易。

截图中的实名额度卡片没有对应后端数据或实名入口，暂不显示该卡片或虚构额度。链上提现仍使用原地址、规则与手续费流程。

测试归属 `test/pages/fund/internal_transfer/`；钱包选币路由与生命周期测试归 `test/pages/wallet/withdrawal/coin_picker/`。测试不发起真实付款。可选实际 Widget 预览通过 `FUND_INTERNAL_TRANSFER_PREVIEW_DIR` 导出，预览账户数据仅存在于测试。
