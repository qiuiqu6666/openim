# 个人表情

`ChatStickerController` 持有收藏上传重试信息并适配 SDK 表情发送；`PersonalStickerStore` 持有账号对应的收藏数据、缓存和更新任务。面板、管理页面、视频表情标记及展示分别有独立文件。

长按自定义图片、GIF、旧 emoji 协议和视频表情可「添加到表情」。控制器提取消息的真实远程地址并调用现有 Store，保留请求 ID 供失败重试，阻止并发重复提交；私密、阅后即焚、未发送成功和无效资源不提供入口。结果提示遵守页面和账号生命周期。

关闭或账号切换后不能继续使用新账号令牌提交旧页面任务。与普通媒体附件共用公共下载、SDK 和图片/视频能力。

聊天里的图片、GIF 和视频表情点击后，通过公共 `chat/stickers/sticker_preview.dart` 打开单个表情全屏预览，复用 `MediaBrowser` 的关闭按钮模式。单击画面或空白背景以及右上角关闭按钮均可退出预览；预览不提供保存、转发、图库、资料或长按菜单。视频静音循环播放，进入预览时停止行内播放，返回后按可见性恢复。

公共媒体浏览器仍保留普通附件的完整工具栏。关闭按钮模式只扩展现有媒体展示参数，未拆分其既有视频渲染职责。

图片、GIF 和视频统一复用公共 `StickerBubbleLayout`，对应参考 99chat 的 `StickerFaceBubble → resolveStickerMessageSize → resolveChatBubbleImageLayoutLimits/DisplaySize` 主消息路径，不采用旧 helper 或引用预览的 0.82 倍规则。手机窄屏/短屏为 132×150，常规屏为 144×160，高屏为 156×176，桌面/平板为 260×230 逻辑像素；最大宽再受消息行可用宽的 54%（桌面 34%）限制。普通资源等比适配；竖长图或顶满高度的细条使用 92 宽的居中裁切预览，高度不超过屏幕档位。实际图片和视频使用 6 逻辑像素圆角、透明背景，表情行边距 16、行底距 12。

按产品要求，OpenIM 的真实时间和回执复用 `ChatItemContainer` 的媒体覆盖层，叠加在表情右下角；仅元信息使用半透明底衬，保留透明 PNG/GIF 的其余区域，不铺普通附件的整宽渐变。正常时间/状态点击穿透到全屏预览，发送失败仍可点击重发，已读开关继续来自 `FriendDisplayPreferences`。极宽的表情框至少保留 32 逻辑像素高度承载元信息，图像仍按比例完整显示；小于元信息的父约束下覆盖层缩小到边界内。图片、GIF 和视频共用同一覆盖层，普通媒体附件保留原有布局。

`ChatImageSticker` 持有图片尺寸和渲染监听。`StickerImageData` 兼容原始 URL、URL JSON 和旧自定义表情 JSON，新发送的个人图片表情携带后端真实宽高。旧消息使用同一图片流首帧探测尺寸并做有界缓存，换源、收到首帧和组件释放时移除探测监听，GIF 渲染继续使用原图片流。未知尺寸使用同屏幕档位的方形占位，加载/失败保持已知尺寸和主题适配的表情图标。

聊天中视频表情不显示播放按钮；任意部分进入可见区域后即静音循环播放，多个可见视频表情分别持有播放器并同时播放，完全离屏时释放播放器。加载或播放失败时保留缩略图，应用退到后台暂停。预览或其他页面覆盖聊天时释放行内播放器，返回后仅恢复当前页面的可见表情。持有消息 ID、本地路径和远程地址的值快照，SDK 原地更新地址时重建播放器并清除旧失败状态。

管理页面逐页加载时检查页面与 Store 生命周期，并要求分页游标推进。页面关闭、Store 释放、分页失败或游标停滞后停止循环；SDK 重复返回同一个游标时 Store 给出可重试错误，避免无限请求和微任务循环阻塞界面。

测试：`test/pages/chat/stickers/`。

内置 99CHAT 表情包的原图目录、四列面板和上传发送适配独立维护在
[`builtin/`](builtin/README.md)。聊天表情栏提供独立 99CHAT 图标，点击图片直接发送；
复用现有 face 消息及预览、收藏协议，保留输入草稿和个人表情入口。

自定义表情栏中的骰子入口、随机结果和发送生命周期维护在
[`dice/`](dice/README.md)。六个用户提供的本地 WebP 按原始帧时长播放，
点数写入 OpenIM custom 消息，历史和失败重试保留原结果。
