# 骰子表情

在现有自定义表情四列面板的添加按钮旁提供骰子入口。复用个人表情面板、聊天发送队列、OpenIM 自定义消息和表情消息容器；输入草稿、消息时间、发送状态和失败重试继续由原聊天模块维护。参考 99chat 的既有表情入口和布局，参考仓库未找到对应的骰子实现。

## 文件归属

- `chat_dice_tile.dart`：面板中的静态骰子入口和发送中状态，颜色来自现有主题；启用 `tightPreview`，按骰子本体的紧凑区域适配现有按钮尺寸。
- `chat_dice_sender.dart`：随机产生一次 1～6 点，创建 SDK 消息并送入原发送链；阻止同时重复发送，关闭、禁言、无效群或账号切换后停止提交。
- 公共包 `chat/stickers/dice/dice_message_data.dart`：骰子协议和严格校验。
- 公共包 `chat/stickers/dice/chat_dice_sticker.dart`：本地 WebP 加载、播放及最终点数展示。
- 公共包 `chat/stickers/dice/dice_webp_frames.dart`：读取原始帧时长、单帧顺序解码，最多缓存六张静态结果供历史和面板复用。
- 公共包 `chat/stickers/dice/dice_webp_playback.dart`：保留当前帧和一个预解帧，按原始帧时长逐帧发布；短期保留播放会话以应对聊天列表重建。
- 公共包 `chat/stickers/dice/dice_sticker_layout.dart`：记录原图方形画布及面板预览区域。聊天播放和静态结果都使用完整画布，面板采用本体裁剪预览。
- 公共资源 `openim_common/assets/chat/dice/`：用户提供的六个原始动画、对应无损静态末帧及来源、校验值。

## 消息与播放

OpenIM 原生 custom 消息的 data 为：

```json
{"customType":906,"data":{"version":1,"value":5}}
```

点数随消息传递；接收端、历史和重发都使用这个值，不再次随机。消息创建失败时可重新点击入口；已创建但发送失败的消息沿用原消息重试。会话摘要显示 `[骰子] 5点`。协议只接受版本 1 和整数 1～6，无法识别的骰子内容显示本地化文字占位。

新近消息可见时按 WebP 原始帧时长播放一次，完成后停留在最终点数。六个素材均为 181 帧、每帧 16 毫秒，源时间合计 2896 毫秒；素材中的无限循环标记不影响聊天的一次播放规则。不按总时钟批量解码并丢弃中间帧，解码落后时保留画面并按顺序继续；实际墙钟时长受设备解码和屏幕刷新影响，没有速度倍率。历史、合并记录及播放完成后的再次进入显示静态结果。播放记录使用账号和消息 ID，设置有界缓存；离屏、后台或聊天被其他路由覆盖时暂停。未完成的列表行重建在五秒内复用同一个解码会话和进度，无人使用的会话最多保留六个；过期后再次进入显示结果，不从头重播。系统开启减少动画时直接显示结果。亮暗主题共用用户提供的透明 WebP 和既有表情尺寸规则。

按用户最新要求，聊天里的骰子间距恢复原样。播放中、落定和历史都保留原来的方形画布，默认使用既有表情的 144×144 占位，不再裁剪聊天留白或在落定时改变高度。消息时间、状态和行距继续使用现有容器。

面板静态预览保留放大效果，使用 `x=104..408、y=196..504` 的完整安全区域，按原有方形按钮缩放本体，骰子可见尺寸约为原来的 1.66 倍。按钮的点击范围、四列布局、发送互斥及载入状态保持原实现，不更改动画文件或帧时长。

静态结果优先读取单帧图片；旧安装包缺少该图片或图片无法解码时，从原动画顺序解码到最后一帧，再缓存结果。新动画播放完成后也直接缓存最后一帧，列表重建无需重新加载结果图片。缓存最多六张，调用者使用独立图像句柄，中间解码帧及时释放；只有原动画也不可用时显示文字占位。

无需上传动画或增加服务端接口；双方客户端需包含此协议和本地资源。没有给通用 custom 消息放开收藏、图片预览或转发权限。

## 验证

测试位于 `test/pages/chat/stickers/dice/`，覆盖严格协议、原 SDK 创建路径、点数随机及发送互斥、账号与页面生命周期、失败重试、面板分页和亮暗布局、六种动画及历史/减少动画/后台播放。逐帧像素比对、注入慢解码、播放中重建、过期不重播和解码未结束时卸载验证本次卡顿修复。相关个人表情、消息状态和会话摘要测试作为回归检查。

六张素材按最终帧点数命名；用户附件的最后两张分别为 6 点、5 点，因此交换为对应的 `dice_6.webp`、`dice_5.webp`。原文件字节保持不变，之前六个骰子 Lottie JSON 已移除。

本地验证使用注入 SDK 和真实 WebP 解码/渲染；两台设备的实际收发和 iOS 构建仍需设备环境验证。

## 开发资源更新

添加 `openim_common` 的动画资源或更改该包的资源清单后，需要完整重新运行 `flutter run` 或安装新 APK。Flutter 热重载的资源变化检测只跟踪主项目的清单和通配目录，长期运行的会话可能继续使用不含新文件的资源包，表现为 `[骰子]`。单独热重载代码不能证明新资源已经进入设备。
