# 聊天资金消息

本目录只负责聊天中的红包、转账卡片及其页面协调。创建、支付、领取、资金详情和真实数据访问继续属于 `lib/pages/fund/` 与现有 FundApi；公共消息协议 `FundMessageData` 继续属于 openim_common。

领取灰字提示由 `lib/pages/fund/notifications/fund_claim_notice.dart` 在真实领取接口成功后通过现有 OpenIM 消息发送器发到订单所属群。聊天消息行直接显示主题适配的居中次级文字，按订单号和领取人去重，领取人必须匹配 SDK 消息发送者。提示是普通客户端信息消息，不作为资金状态依据；旧客户端不会产生该提示，资金后台当前没有接入统一的领取通知协议。单聊和专属红包直接到账，没有领取操作，不生成虚假的领取提示。消息发送失败不影响实际领取，也不会盲目重发。详情页仅增加成功领取后的调用，原领取生命周期与校验仍由该页面持有。

- `chat_fund_controller.dart`：一个聊天路由的可见卡片、刷新去重、60 秒状态缓存、订单校验和资金页面打开状态。
- `fund_card_state_cache.dart`：最多 200 条进程内、响应式的已确认订单展示快照，以服务器、账号及订单号隔离。普通聊天关闭后保留；主页会话关闭时清除并提升会话代次，旧请求不能写回新会话。只保存订单身份、状态、备注和本人领取标记，不保存凭据、密码或完整领取列表，不作为资金操作授权。
- `fund_message_card.dart`：资金消息卡片。
- 领取后的红包卡片只使用原有浅色配色区分，不额外显示“已领取”或“已领完”行，保留标题、总额、数量和页脚。真实领取状态继续保存在控制器/缓存及无障碍朗读中；退款提示、转账状态和聊天领取灰字消息不受此展示调整影响。
- `fund_packet_summary.dart`：红包标题下方的总金额和份数，复用 99chat `red_packet_card.dart` 的粗体金额与次级数量样式。总额来自原资金消息及已匹配订单，群普通/拼手气数量来自订单 `shareCount`；直接到账的单人红包在订单确认收款人后展示一份。没有真实数量时只显示金额，不填造默认份数；资料补齐不会丢失已确认数量。
- `fund_card_recipient.dart`：专属红包和群转账的收款人展示资料，优先查询 OpenIM 群成员资料，缺失时查询用户资料。收款人 ID 只来自已匹配的真实订单；头像、名称不是资金授权依据。专属红包对照 99chat `red_packet_card.dart`，使用圆形收款人头像、收款人专属标题及专属类型页脚；群转账对照 `transfer_card.dart`，使用收款人头像、转账对象标题和独立金额行。资料补齐不提升订单状态版本，账号退出、路由关闭后的旧响应不能写回。
- `fund_card_metrics.dart`、`fund_card_palette.dart`：卡片尺寸和配色。

ChatLogic 创建控制器，注入当前聊天接收人、发送许可、关闭判定和工具栏回调。页面恢复时调用 `refreshVisible()`，页面关闭时调用 `close()`；模块不持有 ChatLogic，也不新增 SDK 订阅。异步订单结果必须仍属于发起请求的账号、登录凭据和服务端；详情返回的较新状态不会被之前的被动刷新覆盖。状态只作为本地展示覆盖，不修改或重发 IM 消息。

发送页的支付成功结果同样回传给控制器，经过会话、聊天目标和订单身份校验后更新卡片展示缓存。服务器产生的 IM 卡片稍后到达时可立即读取已确认状态；旧的被动请求不能覆盖较新的支付结果。取消支付和失效会话的迟到结果不更新当前聊天。

服务端创建的 `contentType: 110` 自定义消息，其 `data` JSON 包含 `orderID`、`biz`、`currency`、`amount`、`status` 和可选 `remark`。备注去掉首尾空白后最多 12 个 Unicode 码点；旧消息缺少备注时兼容为空字符串，超长或非字符串的可选备注安全忽略，不扩大其他自定义消息的识别范围。红包备注作为祝福语显示在卡片主标题，空值沿用默认祝福；转账备注显示在金额下方，并保留真实到账或退款状态。按用户提供的卡片截图，红包标题下方现显示总金额与数量；无障碍明确朗读“红包总额”，不将总额误认成本人领取金额。红包与转账均保留币种和完整金额精度。

消息载荷只是订单快照。GET 订单、详情页返回和支付成功返回的已验证订单，都是状态及备注的权威来源；通过原有订单身份和会话校验后，轻量缓存一并覆盖卡片文案。备注不参与订单身份匹配，旧消息缺少备注不会因此被拒绝。即使状态没有变化、仅备注变化，也会通知响应式卡片刷新；旧订单的备注为空时会清掉消息中的陈旧备注，红包再使用默认祝福。所有更新均为本地展示覆盖，不改写原 SDK 消息，也不重新发送或重复创建资金消息。

进入聊天时，卡片优先同步读取同一账号/服务器、同一资金身份已确认的领取或完成结果，避免先显示旧 IM 消息的未领取样式。旧“未领取”观察可能在另一台手机上改变，必须在本路由重新查询后才确认可领取；没有可信结果时保留红包/转账的 99chat 业务配色，只将状态文字显示为“查看详情”，不宣称可领取。查询进度不切换白色占位配色或卡片阴影，未领取订单从首次绘制到确认后的外观保持一致。网络失败仍保留该业务配色或最近已确认领取的展示，点击详情继续查询真实接口。高对比度模式继续使用现有主题 token。重新查询沿用 60 秒节流和可见卡片去重；跨路由响应版本检查防止旧 GET 覆盖新详情结果，完成或已领取结果不回退为未领取。缓存不会落盘，应用重启后的未知状态仍保留业务配色并查询真实接口。

打开详情时，ChatLogic 传入原 SDK 消息。控制器确认其 `contentType: 110` 及资金单号、业务、币种、精确金额均匹配后，才把 SDK 信封中的 `sendID`、昵称和头像作为可选展示资料传给详情；自定义消息 JSON 中的发送人字段不能替代 SDK 元数据。接口缺少发送人时可补充展示，接口已有身份时优先使用接口。此资料不修改 `FundOrder`，不参与资金授权，也不会触发发消息或自动领取；旧注入回调保持兼容。

卡片移动时保留原有界面实现与公共设计 token。控制器回归测试位于 `test/pages/chat/fund/`；既有卡片测试暂保留 `test/fund_message_test.dart`，其导入已迁入本目录。
