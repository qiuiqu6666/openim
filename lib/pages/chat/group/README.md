# 聊天群状态

## 入群核验与发送限制

SDK 的 `isJoinedGroup` 读取本地群版本列表，返回 false 只能说明本地缺少该群。聊天页进入 `membershipPending`，保留草稿，复用禁用输入栏显示“同步中”，并通过 `GroupMemberIdentitySource.containsMember` 定点请求 `/group/get_group_members_info` 核验当前账号。只有完整、成功且群与用户匹配的响应才可确定成员存在或不存在；网络失败、缺失字段、异常响应和会话变化均不能当作退群。未决查询沿用 1 秒、3 秒的有限重试，连接恢复和同步完成可重新核验。服务端确认在群后不因本地列表仍旧缺失而反复请求。

本人退群/移除事件或服务端确认不存在会立即限制发送并使旧请求失效。本人成员加入事件和加入群列表事件都能恢复；连接/同步恢复期间，已退群状态只能通过新的服务端成员证据解除，本地旧 true、成员资料变更及其他成员加入都不能解除。账号切换、页面关闭和较新的退群事件会丢弃旧核验结果。

`ChatDeliveryController` 在调用 SDK 发送前统一检查当前群发送权限，覆盖文本、附件、重试和转发入口；被拦截时不调用发送接口、不清空草稿、不新增气泡。该逻辑由 Android/iOS 共用，原生 SDK 与其群同步表不作修改。对应回归测试为 `chat_group_membership_recovery_test.dart`、`chat_group_send_guard_test.dart`、成员接口测试和两平台输入栏状态测试。

`identity/group_sender_avatars.dart` 统一同一发送者的历史气泡头像。按当前消息发送者去重，以每批最多 50 人读取 SDK 群成员头像；成员/好友/自身资料事件更新共享显示值。新消息可触发遗漏事件的校准，旧历史页不能覆盖较新头像，查询中的旧返回不能覆盖后到的资料事件。关闭页面或切换账号后丢弃返回，不修改消息发送时存储的原始资料作为显示缓存。

`ChatGroupController` 拥有聊天页的群资料、自己的成员资料、角色、管理员列表、成员名称映射、公告、成员数量和禁言到期计时器。它只订阅当前群的六类 SDK 群事件，不依赖 `ChatLogic`。

页面在会话参数就绪后调用 `initialize()` 和 `recover()`，群资料与历史消息独立加载。首批历史完成、恢复前台、连接成功和同步完成时可再次触发 `recover()`，已成功加载的资料不重复查询。`loadAfterHistory()` 保留为可等待的兼容入口，调用不再依赖历史成功。退出时调用 `close()`。生产入口注入现有 `IMController`、群与账号 getter、消息列表、清空输入和更新群名称/头像的回调。`withSources` 允许测试注入有限的事件流与查询，不初始化全局 SDK。

首次初始化通过 `readCachedGroupInfo` 从账号共享群缓存取得防御性资料快照，同步种入公告正文、公告版本、群名称、头像和成员数量，避免进入群聊后这些区域再次出现。缓存读取仍检查当前账号和退群状态；后台 SDK 独立校准群成员关系、群资料、自己的成员资料与管理员列表，缓存不授予群角色或操作权限。没有真实人数时隐藏人数占位，不显示假 0；空群资料返回保留缓存并进入失败恢复。

群查询复用 `SdkQueryGate`，每次等待上限 15 秒；超时不视为原生请求已取消，重试共享仍未完成的相同查询，每个页面最多四个原生查询在途。失败后最多自动重试两次（间隔 1 秒、3 秒），恢复前台或连接/同步事件可重新给予重试机会。关闭、换账号和明确退群后不写入旧结果，退群停止重试；重新入群使旧查询失效并加载新成员关系。该修复沿用现有群状态模块与 SDK 门控，不新增数据源或界面组件；对照 `reference-99chat/lib/src/chat.dart` 的 `_loadGroupMemberCount` 本地快照显示，正式数据仍来自 OpenIM。

并发历史完成通知共用正在运行的查询。查询后的写入检查关闭状态、群、账号和退群世代；群资料和自己的成员事件还会使对应的旧查询结果失效。成员资料更新每次只刷新一次消息列表。禁言计时器和六个订阅由模块统一释放。

全员禁言先到、自己的成员角色尚未确认时，`muteStatusPending` 表示权限同步中。初始普通成员占位不能作为实际禁言身份；输入区暂时不可发送，静默保留布局高度，不显示同步文字或禁言警告，草稿保留。角色确认后群主/管理员恢复输入，普通成员显示禁言；明确的个人禁言仍按原规则处理。查询失败、空成员或缺少角色不会被当作已确认普通成员，SDK 后续角色事件仍能更新状态。公共输入栏复用原禁用布局，传入空提示并通过 `showDisabledWarning` 隐藏同步期间的警告图标，不新增权限来源或用群缓存授予管理身份。

`announcements/GroupAnnouncementBanner` 由聊天页传入已初始化的 `SharedPreferences`，首帧同步决定当前账号、群和公告版本是否已关闭，不先显示后隐藏，也不在相同资料刷新时临时收起公告。关闭记录按 `version:text` 比较，新版公告仍可出现；「我知道了」的已读记录独立保存。未初始化偏好时保留异步加载，未读弹窗也继续在布局后检查；异步结果校验挂载状态、账号与群键、公告版本及加载代际，旧结果不能改变新的公告。

相关测试位于 `test/pages/chat/group/`，覆盖初次查询、异步关闭/退群、查询与实时事件的先后顺序、成员资料刷新以及禁言和角色。

`member_actions/` 管理聊天消息头像的长按菜单。`chat_member_action_policy.dart` 按当前用户与目标成员的群角色决定 @、专属红包、禁言/解除禁言、移除权限；`chat_member_action_sheet.dart` 复用公共菜单与确认弹窗，`chat_member_action_sources.dart` 接入真实 OpenIM 成员查询、禁言与踢人接口，`chat_member_action_result.dart` 校验原生返回结果，兼容 OpenIM 原生成功回调的 JSON 空字符串。`ChatMemberActionsController` 只协调流程，不新增 SDK 订阅；由 `ChatLogic` 创建并关闭，通过既有成员事件同步成功后的状态。

菜单打开前与执行前定点查询群资料、当前用户和目标成员；菜单/确认期间的群事件使旧操作失效，权限同时受 SDK 资料与最新事件资料约束。禁言沿用 99chat 头像操作的长期禁言时长（315360000 秒），解禁传 0；只有接口成功才更新界面。SDK 即时读取的旧禁言值不会盖住成功回写，写入期间有新事件时不广播旧成员资料。退出成员记录由 `ChatGroupController` 保留，直到明确再次入群，防止缓存让已退出用户重新出现管理入口。

头像操作测试位于 `test/pages/chat/group/member_actions/`，包含角色矩阵、SDK 返回值、菜单亮暗/小屏/横屏/大字、取消、异步关闭、重复长按及权限与禁言更新竞争。对照入口为 `reference-99chat/lib/src/chat.dart` 的 `_onLongPressOthersAvatar` 和成员禁言/移除流程；本项目继续使用 OpenIM 工作群的真实权限规则。

专属红包与 @ 使用相同的发言权限条件。点击后重新核验目标仍在群内，结束加载提示，再调用 `ChatFundController.sendExclusiveRedPacket()` 打开既有 `FundSendPage`，预选专属类型和该成员的 ID、昵称、头像。头像菜单只负责导航；金额输入和支付确认由原有资金页面处理。不同成员或红包类型的待确认支付不能覆盖这个入口预选的接收人。

普通消息不生成 @ 昵称映射；@ 消息只查询其提及的成员。成员变更通过当前消息的发送者/@ 索引定位，仅影响现有消息时触发列表刷新；自身权限、角色、禁言更新保留。成员列表每次构建只获取一次排序快照。
