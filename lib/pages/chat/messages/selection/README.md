# 消息多选

长按消息菜单的“选择”在当前聊天原地进入多选，预选当前消息。`MessageSelectionController` 持有当前会话的消息 ID 集合与操作世代，不保存消息或另建 SDK 数据源。

顶部取消、选中数量，底部逐条转发、合并转发、删除，以及 22px 圆形勾选，对照 99chat 的 `chat_host_app_bar.dart`、`radio_button.dart`、`tim_uikit_chat_history_message_list_item.dart` 和 `tim_uikit_multi_select_panel.dart`。顶部右侧按当前用户要求留空，以等宽占位保持标题居中；选择通过逐条点击和长按滑选操作，新收到的消息不会自动选中。

底部三个图标使用 99chat 多选面板的原始透明 PNG（`images/forward.png`、`merge_forward.png`、`delete.png`），保存在本模块 `assets/*_99chat.png`，由应用资源清单登记该目录打包。按原手机面板的20px图标、2px图文间距显示，使用当前主题和禁用颜色；不再借用长按菜单的矢量图标。三个动作复用既有按钮和回调。

`MessageSelectionRow` 始终保留原消息子节点，进入多选只增加左侧指示器并禁止消息内容点击；输入框通过 Offstage 保留草稿与组件状态。顶部和底部复用公共毛玻璃导航，删除确认复用 Cupertino 底部操作组件。返回键先取消选择。

`MessageSelectionLayout` 的消息和指示器采用固定子节点槽位，退出时停止指示器绘制、命中和语义遍历。布局阶段读取 `ChatMessageContentAnchor` 的实际内容边界，圆点对齐气泡中心，排除时间条、群昵称、行间距和外置回执；异步变高的图片、视频、转写内容在同一布局帧更新。

`MessageSelectionDragRegion` 在多选模式接受手机长按手势，普通滑动交给原列表。起点未选则增加连续范围，起点已选则取消连续范围；缩小范围时恢复手势前的范围外状态。区间按实时消息 ID 顺序计算，跳过通知。手指进入视口边缘时自动滚动，按 controller 实际 axisDirection 及 min/maxScrollExtent 处理，不能假设居中聊天视口的最低位置为零。

拖选每次读取当前挂载行的几何边界，保存的起点 ID 不依赖懒加载行是否仍挂载。松手/取消、起点删除或过期、开始批量操作、退出多选、路由覆盖、应用后台和销毁均停止手势与 ticker。连续范围和边缘速度参考 99chat 的桌面 `desktop_message_drag_select.dart`；此处适配手机长按及当前 OpenIM 列表，不引入跨聊天静态选择状态。

消息窗口更新时同步剔除已删除、撤回和过期移除的 ID。取消、关闭或账号变化使异步结果失效；操作期间不能重复提交或开启第二批操作。成功后退出，取消联系人选择或全部明确失败时保留选择，支持重试。部分成功或发送状态不确定时退出多选并提示核对目标聊天，避免整组盲目重试造成重复消息。

操作复用 `ChatMessageActions.deleteMessages` 和 `ChatForwardingController.forwardMessages`：SDK 本地删除成功后走既有历史/缓存、语音、引用、复制状态失效；资金卡不批量删除。转发重新校验全部选中消息，私密、失败或不支持的消息阻止整个操作。逐条最多30条，合并保留原流程的100条限制；联系人只选一次，按稳定时间顺序发送，依据发送回执判断结果，保留当前输入草稿。

状态和组件测试位于 `test/pages/chat/messages/selection/`，SDK 操作适配测试位于 `test/pages/chat/messages/` 的对应子目录。亮暗主题、小屏、大字体、消息子状态、底部确认与会话失效都需要验证。真实跨设备送达和系统手势仍需真机验收。
