# 消息发送与操作

`ChatDeliveryController` 持有发送状态流，协调已有 `ChatMessageSender`、当前会话的消息窗口、输入重置及失败提示。关闭与账号变化后停止提交操作，并拒绝迟到结果修改页面。测试可注入真实发送接口的替代实现。

`ChatMessageActions` 管理转发/撤回菜单策略、SDK 撤回删除以及成功后的本地失效通知。`forwarding/` 管理单条/批量/合并转发和联系人名片；`selection/` 管理当前聊天的多选、全选和操作栏；`presentation/` 管理通知/失败提示气泡策略；`widgets/` 管理聊天消息行、菜单和内容展示。

资金卡片仍由资金模块及后端创建，不能通过 IM 撤回、普通转发或重发制造订单状态变化。收藏发送状态契约仍复用已有共享服务，后续整理收藏模块时处理其历史依赖关系。

测试：`test/pages/chat/messages/`；跨模块入口验证：`test/integration/chat/`。

`custom/` 是聊天时间线与会话长按预览的共享自定义消息展示入口。已知
资金/通话/关系提示和 AI 工具卡片使用原组件；资金实时状态仍由聊天
控制器提供。正文保留换行和 Markdown，未知协议显示原文/JSON，只有
空 data 才使用 description。预览不创建聊天控制器或业务操作回调。

自动最新窗口接收时将追加与裁剪合并成一次通知，保留发送中/失败消息；历史阅读不执行最新端的自动裁剪，多选时不裁剪。历史分页自己的双向窗口策略见 `../history/README.md`。红包领取提示使用页面级首条索引和按消息弱引用的解析缓存，仍验证 SDK 发送者，变更载荷会重新解析。

`chat_message_index.dart` 缓存反向消息 ID、索引与持久消息集合。列表通知只标记待核对，实际构建时比较 ID 顺序；回执等不改变 ID 的更新复用集合。焦点、加载状态及动画完成刷新不重建 SDK 索引；换控制器和卸载时释放对应观察者，临时展示行继续使用独立映射。

发送确认、失败和附件阶段更新复用 `refresh/` 的行通知；已挂载的目标气泡刷新，不因状态变化重建整个列表。合并 SDK 消息时保留提前到达的已读状态及本地时间标记；SDK 修正发送时间时仍刷新时间线，保证相邻时间分隔线正确。完成后释放上传通知器与计时器，未知结果继续允许核对；迟到查询不能复活已经完成的上传状态。重复百分比回调不重建 30 秒停滞计时器。

`presentation/chat_copy_text_cache.dart` 按最近渲染/复制保留最多 600 条文本。离开窗口的正文重新显示时可重新生成，长时间收发和翻阅不再累积所有历史文本；撤回、删除、清空和退出仍释放对应内容。保留 `Map` 接口与带昵称的复制行为。
