# 当前会话窗口发布契约

版本 1 的 `MessageWindow` 由 Core 经现有历史接口返回。Flutter SDK 不从全局同步状态推断首屏可见性。请求使用 `messageWindow: true`，本地读取使用 `getLocalMessageWindow`；有锚点的历史分页继续走现有接口。

## 状态与身份

`readiness`、`source`、`coverageStatus`、`publishable` 是独立维度。本地完整窗口为 `local / ready / covered`；远程固定水位校验完成为 `remote / ready / covered`。缺口窗口为 `preparing / partial`，不会发布。网络/存储失败沿现有 SDK 错误通道返回，已有本地窗口继续可读，无窗口时显示重试入口。不能把超时解释为空历史。

`targetWatermark` 是本次准备的固定水位；`latestServerSeq` 是本次远程查询获得的服务端序号，本地读取的 0 表示未知。`covered`/`missing` 描述 `[lowerBound, targetWatermark]` 的覆盖，包含已删除和不显示的控制消息；最后一条可见消息可能小于水位。仅有消息数量或 `publishable=true` 不足以通过 Dart `canPublish` 校验。

`conversationID` 与页面所有者、账号、令牌、请求 generation 共同隔离异步请求。`snapshotRevision` 是窗口内容摘要，表示身份，不是可比较的服务器变更游标。页面只接受有效所有者的结果，不将较小水位覆盖已发布窗口；过期页面不会阻止 SDK 向原会话数据库提交合法数据。

## 覆盖与变更一致性

Core 在 SQLite 同一读取事务内获取会话边界、消息和持久化撤回覆盖，并从实际已提交行推导覆盖证明。不存在可提前写入、崩溃后残留的“完整”标志。原有消息批次事务负责写库和检查点，事务失败不能确认消息页。进程在提交前/后被杀的测试验证回滚、完整重启及幂等重放。

远程准备固定最新水位，通过现有带方向的历史接口确认用户可见范围，重读有界窗口内全部消息，以覆盖离线期间较早序号的撤回。实时/离线通知仍使用现有独立通知序号和持久化撤回、已读处理；本地删除及已撤回内容不会被旧普通快照恢复。本仓库没有通用消息编辑协议，本轮没有宣称或新增任意编辑版本流。

`visibilityKey` 使用会话可见序号边界和私密属性，群/会话/账号变动清除相关缓存。内存缓存最多 8 个窗口、有效期 30 秒，按最近使用淘汰；内存压力时清空，不缓存私密消息。离线窗口代表最后已知权限和数据，不能保证服务器尚未通知的最新权限；远程读取重新核对权限。服务端未落盘/预分配空槽返回可重试错误，只有明确删除记录才能提供不可见序号覆盖。

## 有界准备与增量接入

默认准备 40 个序号，单页最多 100；全为不可见消息时最多再检查两页，总计不超过 300 个序号，之后返回可续读游标。水位不随新消息持续增长，避免大群首屏永远追不平。这个窗口不是整段历史同步完成的证明。

实时可靠持久化沿 SDK 原有接收路径进行。展示队列最多 200 条、默认 16ms 合并发布，缺号时暂存并触发合并恢复。溢出只释放展示副本，回读已持久化数据，不静默丢弃接收消息。到底部时展示窗口裁剪到 600 条附近；阅读历史时保留阅读窗口并通过现有新消息提示承接后续消息。批次更新保留消息稳定 ID，不按时间戳重排服务端消息；未获得序号的发送中消息保持临时身份，确认后去重衔接。

首批本地读取和导航预读共享请求/缓存；其他会话的新消息不会导致重复准备。读取失败、退出、清空和账号变化取消展示侧计时器并拒绝旧结果。真实消息就绪直接显示，保持真实列表实例；已读仍由页面有效性和实际视口确认控制。媒体尺寸和滚动锚点继续复用现有专用组件，不增加首屏等待全局同步的条件。

## 进入计时与预热

进入计时从会话点击处理开始，分别记录 `prefetch_start`、本地准备开始/结束、`route_push`、`init_start`、`window_ready`、`first_correct_message_frame`、`list_interactive` 和 `transition_finished`。正确消息帧须满足窗口可发布、视口含真实消息、内容已绘制且非全透明、当前页面有效；它表示 Flutter 绘制提交，不是屏幕扫描输出。空会话单独记录 `first_empty_frame`。记录只含计时、入口编号和会话类型，不含账号、消息或令牌。

`list_interactive` 要求消息已绘制、列表允许触摸，不等待入场动画结束；返回动画、返回手势和后台页面不能取得该里程碑。`transition_finished` 由独立的路由状态监听记录，不等待消息就绪；因此慢读取时可以先结束转场，再出现正确消息帧和可操作列表。减少动态效果时，视觉转场在首个有效帧直接完成。组件测试实际点击进入中的列表，同时校验反向返回/手势阻止输入时不会误报。

会话列表通过可见行检测，在停止滚动 150ms 后仅预取最多 8 个可见会话，每个 40 条，最多两个本地请求并发。不遍历整张列表，不启动网络历史请求；切换标签、覆盖页面、进入后台或退出账号时停止后续调度。点击会话仍复用导航预读及 SDK 的同代次在途请求；内存窗口缓存保留 30 秒，最多 8 个会话。新消息、会话变化、撤回、删除和账号变化沿用现有失效链，下一次读取重新取得证明，不手工拼接过时快照。

页面初始化同步消费已准备好的证明，未命中时异步读本地数据库，不等待网络或其他会话同步。真实消息立即渲染并允许触摸，不播放骨架或淡入，也没有最短等待时间；仅无可发布窗口超过 200ms 时显示轻量文字提示。错误、扫描限制和确认空会话仍走现有状态。后台补齐复用原有窗口、连续性与阅读锚点策略：缺口事件暂存，阅读中保留当前窗口，连续实时消息正常追加。路由转场与记录就绪独立计时。


## 兼容与回退

接口是现有历史 JSON 的可选字段扩展；旧 SDK 无版本化证明时走既有兼容路径，不能当作新契约的就绪证明。没有新增数据库表/完整标志或破坏性迁移。客户端回退使用上一安装包和对应锁定原生 SDK；不能只换 manifest 混用 AAR。服务端回退用部署目录备份二进制恢复消息 RPC 服务，源码补丁独立保存。

Android 最终包包含会话窗口与消息恢复补丁，精确版本及二进制哈希以对应安装包的验证报告为准。iOS 共享源码已包含契约，但本轮没有 macOS Framework 构建和 iOS 真机结果。窗口原子性验证证据见 [recovery.26-chat-window.json](../../../../native_sdk/patch15/verification/recovery.26-chat-window.json)。
