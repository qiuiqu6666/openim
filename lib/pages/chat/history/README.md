# 聊天消息窗口与历史

- `chat_timeline_controller.dart`：一个聊天路由的消息列表、缓冲消息、删除 ID、加载状态、时间分隔和安全的首屏快照生命周期。
- `chat_history_loader.dart`：SDK 首批、旧页、同步/前台刷新、当前页面日期定位、双向分页及失败重试的请求协调、游标和合并。
- `chat_history_prefetcher.dart`：导航开始时提前读取 SDK 本地首批历史，聊天路由复用同一次请求；未进入的请求两秒后过期，最多保留 12 个，不建立额外的持久化消息库。
- `date_jump/`：点击消息之间的时间提示打开日历，只有有真实聊天记录的日期可点击；未知、无记录、加载失败的日期禁用。点选后再次复核当天记录，用 SDK 按本地自然日查找记录并在当前聊天页面定位。目标已在消息窗口时直接滚动；未加载时由 timeline 安装目标前后的有界连续窗口，可继续加载更早或更新记录，保留输入框及草稿。取消只关闭日历，不触发窗口定位。

日期可用性复用 `history_search/selection/date_availability/`，仅查询显示月份的逐日记录，每个日历最多三个在途查询；切月和恢复前台会重新校准。当前会话已加载的表情、富文本或群通知等 SDK 不可搜索类型也可证明当天有记录，并沿用原定位能力；删除 ID、会话失效及 SDK 双闭午夜边界均继续过滤。取消、后台恢复、新路由覆盖和销毁不能使旧日期复核关闭新页面或发起过期定位。

日期跳转弹窗开启 `includeDayImages`：确认当天有记录后，在同一个请求槽内查询当天图片，最多从一页 20 张有效候选中随机选一张缩略图作为日期圆形背景；若 SDK 返回整页次日午夜边界则继续到当天页。日期与图片采用同一本地自然日范围，不显示已删除、私密、过期或无有效地址的图片。同一弹窗保留选中的图片，重新校准时仍在有效候选中的图片保持不变，否则重新选择或恢复普通日期。图片查询或加载失败不影响日期可用性；账号失效或销毁时清理图片缓存。聊天记录搜索的独立日期页默认不请求图片。

弹窗复用应用表面色、蓝色强调色和圆角。标题与日历一起滚动，整宽取消按钮保持在可见区域；`date_jump/widgets/chat_date_image_calendar.dart` 使用公开 `YearPicker` 与固定六周日期格保留月份、年份选择，左右滑动日期区域也可切月，并沿用本地语言方向及日期范围。图片加载成功且再次通过账号、删除和图片身份检查才显示暗色遮罩与白色日期，选中及今天使用蓝色标识；加载中、失败或失效后恢复普通日期。窄屏日历沿用横屏文字缩放上限，两位日期单行缩放避免裁剪，其余标题和按钮按系统字号缩放。样式集中在 `date_jump/widgets/chat_date_picker_style.dart`。

搜索结果返回实际聊天页后也复用同一窗口与定位接口。缓存首屏只有展示快照，真实 SDK 尚未装入游标或原分页/刷新仍在途时，定位会安装新的目标窗口并使旧请求失效；稳定已加载窗口才直接定位现有消息。

公共 `ChatListView` 在用户滑动到更早/更新边界时自动请求对应 SDK 页，短列表依据手指 overscroll 方向选择分页；两端共享加载保护，受控 newer 边界随当前窗口更新。loader 的窗口世代经 timeline 和路由传到列表的 `pagingWindow`，只有定位、返回最新、清空或取消窗口替换才变化；普通分页和实时加行保留当前加载归属。旧窗口迟到的回包、异常和结束回调不能堵住、解除或改写新窗口的加载状态。加载后沿用消息 ID 锚点保持阅读位置，失败可重试。

ChatLogic 创建并关闭 timeline。`initialize()` 注册一次列表观察、读取可用快照和 latestMsg、默认提前加载首批历史；路由需要保留初始化时序时可传 `prefetch: false`，完成其他初始化后调用 `loadOlder()`。真实数据通过注入的 SDK history 请求读取，不注册重复 SDK 监听。

会话 ID 和账号属于创建本路由时的固定范围；会话对象使用 getter，使私密模式变更仍能阻止缓存。进程级 ChatHistoryCache 保持公共服务归属，写入验证当前账号、缓存 epoch 和会话清理版本，过滤私密消息、typing 和已删除 ID；注销或删除会话后旧路由不能重新写回缓存。预读请求另外检查令牌和会话清理版本，私密会话直接读取 SDK。

路由注入 `isSessionCurrent`，正常关闭可以保存最终快照，同账号令牌更换后不能保存旧会话快照。批量删除超过有界删除记录窗口时推进 epoch，使旧预读重新从 SDK 获取，同时停止使用可能已经过时的 `latestMsg` 首屏种子；保留快照的容量上限，避免无限增长删除 ID。

历史合并在请求开始时保存发送状态值，在结果返回时对照当前状态，避免旧快照将成功或失败的消息改回发送中。正在发送的本地消息保持对象身份，SDK 结果和发送回调更新同一个对象；请求期间刚完成发送的消息即使尚未进入 SDK 历史页也会保留。

timeline 不持有滚动控件、语音、引用或 ChatLogic。首批/不连续窗口由 `onFirstPage` 处理滚动；普通刷新经 `captureOffset`、`restoreOffset` 恢复位置，路由负责下一帧调度、范围限制和关闭保护。删除只处理 timeline 和缓存，路由再通知语音/引用等模块。清空返回受影响 ID，并使旧请求和已排队刷新失效。

正常实时消息由路由直接添加到消息窗口，滚动位置保持交给公共 `ChatListView`。日期定位的历史窗口与最新记录尚未连接时，路由把实时消息放入 `scrollingCacheMessageList`，避免将不连续的记录拼接到历史窗口；向后分页到 SDK 最新边界后 `loadNewer()` 自动合并缓冲，或由路由在 `returnToLatest()` 成功后合并。新消息提示数量属于独立的 `scrolling/` 模块，不能使用历史加载条数或 SDK 会话未读数代替。

`jumpTo(target)` 和 `returnToLatest()` 返回操作成功与否；`loadOlder()` 和 `loadNewer()` 返回对应方向是否还有记录，两个方向共用 `historyLoading`，不并发安装窗口。SDK 向前和向后读取分别注入 `fetch` 与 `fetchNewer`；后者未提供的既有调用方仍保留单向分页行为。`viewingHistory` 在定位请求开始时置为 true，使实时消息立即进入缓冲；成功安装后由 SDK 最新边界决定，失败恢复已安装窗口的状态。重复定位、返回最新、清空与关闭使旧查询失效，旧请求完成不能释放新请求的 loading 所有权或改写列表。

用户手动滚动时，路由可调用 `cancelWindowChange()` 取消尚未安装的日期窗口或返回最新请求，保留当前记录和两端游标，丢弃迟到结果；已失败的窗口替换也会清理其重试和错误状态，避免取消后再次跳回旧目标。普通历史分页及其失败重试不受该取消操作影响。分页游标修复只使用 SDK 已确认的历史窗口成员，避免刚完成发送的保留消息跨过尚未加载的记录。

`date_jump/chat_date_window_controller.dart` 协调 SDK 消息窗口与公共 viewport 的定位。`retry()` 重走失败的完整日期跳转（恢复同一目标并定位）或返回最新（合并实时缓冲并滚到最新），不重复日期搜索；普通分页失败回退 timeline 的对应方向重试，到达最新后再合并缓冲。只有当前请求的失败可以保存动作；新动作、成功、手动取消及关闭会清理旧失败，旧请求结束不能覆盖新请求的状态或重试目标。

历史窗口状态下的同步/前台 `refresh()` 保持当前窗口，由现有 SDK 实时回调处理回执及删除；它不请求最新页，避免跳回最新或制造历史缺口。失败重试保留操作类型及日期目标。历史和定位中窗口不写入最新首屏缓存，关闭后原安全缓存仍可供下一次进入使用；私密模式变化、删除与账号失效仍按原规则清理缓存。

关闭时刷新安全快照、停止列表观察和缓存计时器、关闭历史请求接收。SDK 回调和订阅仍由 ChatLogic 按原有所有权清理，避免旧页面关闭影响后继页面。

日期定位优先使用当前窗口已加载的当天记录（包括 SDK 无法搜索的消息类型），否则只在当前会话查询 SDK 支持搜索的消息类型，跳到当天的一条记录，可继续加载前后文。日界线使用本地午夜，SDK 请求单位是秒，消息时间是毫秒；过滤包含式查询的次日午夜，跨夏令时用相邻午夜计算时长。SDK `totalCount` 仅表示本页条数；仅当整页都是边界消息或已移除消息时继续翻页。页面关闭、会话清空、账号/令牌变化后丢弃迟到结果，重复点击不叠加弹窗或查询。

验证入口：`test/pages/chat/history/` 和 `test/integration/chat/`，覆盖真实 ChatLogic 初始化、首屏预读复用、发送状态与对象身份、私密过滤、账号/令牌/epoch/会话清理版本、清空/关闭晚到结果、同步合并和分页窗口。

## 高频消息与恢复

- 自动收消息时，最新窗口上限 600 条，发送中与发送失败消息保留；用户主动翻页读取的历史不按此限制裁剪。
- 阅读旧消息且达到上限后，沿用历史窗口模式，保留阅读位置；仅缓存最近 100 条实时消息快照。所有完整消息仍由 SDK 持久化，向新消息方向翻页或点击回到最新后读取连续区间。
- 重连拉取的新页面与旧窗口不连续时，正在读旧消息的用户留在原窗口。回到最新时丢弃 SDK 最新边界之前的缓冲快照，避免拼接不连续区间。
- 同步、历史加载、加载失败或历史窗口期间不自动清空整个会话未读；恢复前清除旧的 viewport 可见授权，重新绘制后才能确认已读。私密消息仍按真实可见内容确认。
- 公共 viewport 使用消息 ID 对应的 GlobalKey 保留可见气泡子树；仍允许 sliver 更换坐标原点，避免破坏原有滚动修正。

测试覆盖万条实时消息、离线大间隔保留阅读窗口、连续分页、发送状态、私密已读和可见气泡状态保留。离线新增消息的精确条数依赖 SDK 会话未读，未虚构离线入场计数。
