# 聊天消息窗口与历史

## 后台刷新与翻页加载

`historyLoading` 继续表示真实读取占用，用于互斥、恢复与已读协调；`historyPagingLoading` 仅控制列表加载行。已加载窗口的后台 `refresh()` 不插入历史加载行，首屏、显式翻页及日期定位仍展示加载。不能根据 `hasMore=false` 禁止后台刷新，因为历史结束后仍可能收到新消息。回归见 `chat_background_refresh_loading_test.dart`。

全局 native wake / sync ended 只刷新首轮同步未确认、尚未加载、正在读取、存在前后台/断线检查点、遮挡期间有消息或读取失败的窗口。正常可见会话由实时消息及缺失最新摘要恢复处理，不随其他会话的同步失败周期重复查询。真实连接断开记录待恢复检查点。回归见 `chat_foreground_recovery_test.dart` 的连续三轮全局恢复用例；重叠恢复用例从真实前台恢复启动，保留请求合并与有限重试检查。

## 冷启动本地首屏

`ChatTimelineController` 在内存首屏不足时并行发起一次 SDK `getLocalHistorySnapshot`，无需等待最新历史的网络校验。Core 只读取当前会话最多 40 条本地行（接口硬上限 100），过滤删除、typing、私密消息和本地可见下限之外的消息；不补洞、不维护缓存、不更新分页游标或已读。响应必须带 `localSnapshot=true` 才可展示，旧 SDK 未确认的响应忽略。

本地结果仅是展示快照，不能单独设置 `loaded`、结束加载或确认云端历史已到末尾。真实历史请求仍独立运行。尚未绘制时可直接安装回包；已有真实 viewport 观察且回包包含更晚消息时，将原列表保留为历史阅读窗口，保存原先的前后分页锚点，绝不把回包拼接到旧范围。结束本次读取但继续禁止整个会话已读，显示“有新消息”，不将回包条数冒充缺口中的总数。同步刷新及自动较新分页不能绕过此保护。用户仍可向更早方向翻页。

点击提示后重新读取最新窗口，网络等待期间原记录仍可阅读；成功时先短淡出，再安装并定位最新窗口，下一帧淡入。整个过渡由 `ChatDateWindowController` 协调，只有显式点击后的窗口切换使用此过渡，普通实时消息沿用原滚动动画。减少动画设置跳过淡出等待；手势打断、清空和页面关闭会使未安装的回包失效。失败保留原窗口和提示，可重试。较早记录由新窗口的 SDK 游标按需回读，不跨缺口合并。

实时收发继续保留。清空、删除、撤回、窗口定位、页面关闭、账号/令牌变化、私密模式变化和 SDK 已先返回时均有失效保护。验证包含 `chat_deferred_history_cases.dart` 的 20 条新消息、历史缺口、正在阅读旧消息、前后位置不变、过渡取消与失败重试，以及 `chat_deferred_paging_test.dart` 的分页锚点衔接。

此优化复用 SDK 数据库，没有新增磁盘消息副本。冷启动后已有记录可提前显示；首次安装、清空数据或本地无有效行仍等待真实历史。相同账号、令牌、缓存世代、会话修订和条数的在途最新读取复用同一个原生请求；完成后的刷新仍重新查询。`chat_history` 日志增加本地首屏条数和耗时，不记录消息正文。

验证：`chat_local_snapshot_test.dart`、`chat_entry_performance_test.dart`、`chat_history_prefetcher_test.dart`；Core `history_snapshot*_test.go` 覆盖断网、真实 SQLite 重开、删除/私密过滤、游标与未读不变。ChatLogic 仅增加依赖注入，实际职责保留在 history 模块；不扩展超长路由控制器的业务实现。

## 离线恢复中的空刷新

已加载窗口的普通同步/前台刷新返回空消息、且没有扫描预算让出标记时，保留消息与原有分页边界。`isEnd` 只结束本次查询，不是删除已有消息的凭据。首屏已有快照或显式返回最新时，空替换保留当前窗口并交由现有有限重试处理，不确认首屏已加载或据此开启已读。明确删除、清空、账号代次切换继续生效；日期定位仍安装各自确认的窗口。回归见 `chat_empty_refresh_test.dart` 和 `chat_recovery_overlap_test.dart`。

## 有界扫描续读

SDK `scanLimited` 表示本次扫描让出预算，不表示历史结束，也不作为 SDK 错误。`scanCursor` 独立记录已验证范围的末端，包括删除占位的位置；它不进入显示消息列表。前后分页与日期窗口保留各自扫描位置，续读失败仍保留位置，重试不会退回空游标。同步刷新不自动重启已暂停的扫描；页面沿用现有状态按钮显示“继续加载历史消息”，需明确点击后再读一批。真正结束仍由 SDK `isEnd` 确认，真实错误响应仍不安装整页。

`chat_history_diagnostics.dart` 向原生日志写入请求方向、游标、可见条数、预算让出状态、重试次数及重置来源，发布版也保留这些结构化证据；不记录消息正文。相同同步/连接状态重复发布不重置历史重试预算。

SDK 同步中不再暂停可见页面的最新消息补读、失败历史恢复和回前台缺口恢复。读取继续遵守页面可见性、账号代次、日期窗口及在途请求上限；SDK 同步结束仍可触发一次恢复。已读上报继续保留同步中和未补齐窗口的保护，避免把未展示消息标成已读。回归：`test/integration/chat/chat_recovery_overlap_test.dart` 的同步中补读用例。

- `chat_timeline_controller.dart`：一个聊天路由的消息列表、缓冲消息、删除 ID、加载状态、时间分隔和安全的首屏快照生命周期。
- `chat_history_loader.dart`：SDK 首批、旧页、同步/前台刷新、当前页面日期定位、双向分页及失败重试的请求协调、游标和合并。
- `chat_history_read_gate.dart`：历史读取等待默认 30 秒后进入现有错误/重试状态；超时不当作原生取消。每个路由最多保留两个未完成读取（含已超时请求），普通同窗口同游标重试复用在途 Future，日期定位前后页共享额度。迟到响应不能通过已超时的等待写入窗口；窗口世代仍由 loader 校验。此限制不覆盖其他路由或独立日期搜索，请求真正不返回时仍需 SDK 层恢复。
- `chat_history_window.dart`：连续翻页完成时保留靠近当前翻页端的 600 条非待发消息，发送中/失败对象额外保留。只有 ChatLogic 确认页面当前可见、非多选/日期定位、读取完成后仍在该翻页端一屏范围内才允许裁剪。向旧记录翻页裁掉较新端时建立 newer 游标和历史模式；反向翻页裁掉较旧端时更新 older 游标并恢复 hasMore。裁剪不删除 SDK 消息，不改变窗口世代，继续使用消息 ID 锚点恢复阅读位置。缺少反向 SDK 接口或未提供裁剪资格的调用方保留原行为。
- `chat_history_prefetcher.dart`：导航开始时提前读取 SDK 本地首批历史，聊天路由复用同一次请求；未进入的请求两秒后过期，最多保留 12 个，不建立额外的持久化消息库。
- `date_jump/`：点击消息之间的时间提示打开日历，只有有真实聊天记录的日期可点击；未知、无记录、加载失败的日期禁用。点选后再次复核当天记录，用 SDK 按本地自然日查找记录并在当前聊天页面定位。目标已在消息窗口时直接滚动；未加载时由 timeline 安装目标前后的有界连续窗口，可继续加载更早或更新记录，保留输入框及草稿。取消只关闭日历，不触发窗口定位。

日期可用性复用 `history_search/selection/date_availability/`，仅查询显示月份的逐日记录，每个日历最多三个在途查询；切月和恢复前台会重新校准。当前会话已加载的表情、富文本或群通知等 SDK 不可搜索类型也可证明当天有记录，并沿用原定位能力；删除 ID、会话失效及 SDK 双闭午夜边界均继续过滤。取消、后台恢复、新路由覆盖和销毁不能使旧日期复核关闭新页面或发起过期定位。

日期跳转弹窗开启 `includeDayImages`：确认当天有记录后，在同一个请求槽内查询当天图片，最多从一页 20 张有效候选中随机选一张缩略图作为日期圆形背景；若 SDK 返回整页次日午夜边界则继续到当天页。日期与图片采用同一本地自然日范围，不显示已删除、私密、过期或无有效地址的图片。同一弹窗保留选中的图片，重新校准时仍在有效候选中的图片保持不变，否则重新选择或恢复普通日期。图片查询或加载失败不影响日期可用性；账号失效或销毁时清理图片缓存。聊天记录搜索的独立日期页默认不请求图片。

弹窗复用应用表面色、蓝色强调色和圆角。标题与日历一起滚动，整宽取消按钮保持在可见区域；`date_jump/widgets/chat_date_image_calendar.dart` 使用公开 `YearPicker` 与固定六周日期格保留月份、年份选择，左右滑动日期区域也可切月，并沿用本地语言方向及日期范围。图片加载成功且再次通过账号、删除和图片身份检查才显示暗色遮罩与白色日期，选中及今天使用蓝色标识；加载中、失败或失效后恢复普通日期。窄屏日历沿用横屏文字缩放上限，两位日期单行缩放避免裁剪，其余标题和按钮按系统字号缩放。样式集中在 `date_jump/widgets/chat_date_picker_style.dart`。

搜索结果返回实际聊天页后也复用同一窗口与定位接口。缓存首屏只有展示快照，真实 SDK 尚未装入游标或原分页/刷新仍在途时，定位会安装新的目标窗口并使旧请求失效；稳定已加载窗口才直接定位现有消息。

公共 `ChatListView` 在用户滑动到更早/更新边界时自动请求对应 SDK 页，短列表依据手指 overscroll 方向选择分页；两端共享加载保护，受控 newer 边界随当前窗口更新。loader 的窗口世代经 timeline 和路由传到列表的 `pagingWindow`，只有定位、返回最新、清空或取消窗口替换才变化；普通分页和实时加行保留当前加载归属。旧窗口迟到的回包、异常和结束回调不能堵住、解除或改写新窗口的加载状态。加载后沿用消息 ID 锚点保持阅读位置，失败可重试。

ChatLogic 创建并关闭 timeline。`initialize()` 注册一次列表观察、读取可用快照和 latestMsg、默认提前加载首批历史；路由需要保留初始化时序时可传 `prefetch: false`，完成其他初始化后调用 `loadOlder()`。真实数据通过注入的 SDK history 请求读取，不注册重复 SDK 监听。

会话 ID 和账号属于创建本路由时的固定范围；会话对象使用 getter，使私密模式变更仍能阻止缓存。进程级 ChatHistoryCache 保持公共服务归属，写入验证当前账号、缓存 epoch 和会话清理版本，过滤私密消息、typing 和已删除 ID；注销或删除会话后旧路由不能重新写回缓存。预读请求另外检查令牌和会话清理版本，私密会话直接读取 SDK。

路由注入 `isSessionCurrent`，正常关闭可以保存最终快照，同账号令牌更换后不能保存旧会话快照。批量删除超过有界删除记录窗口时推进 epoch，使旧预读重新从 SDK 获取，同时停止使用可能已经过时的 `latestMsg` 首屏种子；保留快照的容量上限，避免无限增长删除 ID。

历史合并在请求开始时保存发送状态值，在结果返回时对照当前状态，避免旧快照将成功或失败的消息改回发送中。正在发送的本地消息保持对象身份，SDK 结果和发送回调更新同一个对象；请求期间刚完成发送的消息即使尚未进入 SDK 历史页也会保留。

所有 loader 读取在 `ChatHistoryReadGate` 检查 `AdvancedMessage.errCode`：非零码即使附带部分消息，也将整页作为失败处理，保留 SDK 错误码与说明，进入原有失败重试流程。首屏、前后分页、同步刷新、日期定位和返回最新共用此检查；失败响应不安装消息、不推进分页边界，也不触发加载成功回调。成功码为零或未提供时沿用正常处理，迟到错误仍受窗口世代与关闭检查约束。

timeline 不持有滚动控件、语音、引用或 ChatLogic。首批/不连续窗口由 `onFirstPage` 处理滚动；普通刷新经 `captureOffset`、`restoreOffset` 恢复位置，路由负责下一帧调度、范围限制和关闭保护。删除只处理 timeline 和缓存，路由再通知语音/引用等模块。清空返回受影响 ID，并使旧请求和已排队刷新失效。

正常实时消息由路由直接添加到消息窗口，滚动位置保持交给公共 `ChatListView`。日期定位的历史窗口与最新记录尚未连接时，路由把实时消息放入 `scrollingCacheMessageList`，避免将不连续的记录拼接到历史窗口；向后分页到 SDK 最新边界后 `loadNewer()` 自动合并缓冲，或由路由在 `returnToLatest()` 成功后合并。新消息提示数量属于独立的 `scrolling/` 模块，不能使用历史加载条数或 SDK 会话未读数代替。

ChatLogic 分别持有 `chatMessageEvents` 和 `c2cReadReceipts` 的订阅，不再占用全局接收回调槽。普通、离线、在线临时和本地注入消息保留来源，复用会话过滤、去重和账号/令牌校验；离线消息不补发通知。关闭任一聊天只取消它自己的订阅，栈中的其他聊天继续接收。

被页面覆盖时，普通消息进入最多 100 条的原缓冲，暂停同步刷新；返回后查询最新历史并等待重新绘制，再允许会话已读。日期历史窗口仍按原规则保留连续区间。迟到旧消息按与历史合并相同的时间、SEQ 比较规则二分插入，正常递增消息快速追加。

`ChatHistoryRecovery` 合并重连成功和原生唤醒提示，仅对前台当前页、非 SDK 同步中的失败窗口间隔 1 秒、3 秒最多重试两次。新的前台、连接、同步完成或唤醒事件更新重试预算，内部失败完成不能自行更新预算。提示或计时器到达时历史仍在读取，会等该读取结束后检查错误；旧窗口重试期间收到的新恢复请求不能被旧结果吞掉。重试保留日期目标、分页方向和滚动恢复动作。健康窗口由独立的前台/同步刷新协调，关闭页取消等待，手动重试继续保留。

`jumpTo(target)` 和 `returnToLatest()` 返回操作成功与否；`loadOlder()` 和 `loadNewer()` 返回对应方向是否还有记录，两个方向共用 `historyLoading`，不并发安装窗口。SDK 向前和向后读取分别注入 `fetch` 与 `fetchNewer`；后者未提供的既有调用方仍保留单向分页行为。`viewingHistory` 在定位请求开始时置为 true，使实时消息立即进入缓冲；成功安装后由 SDK 最新边界决定，失败恢复已安装窗口的状态。重复定位、返回最新、清空与关闭使旧查询失效，旧请求完成不能释放新请求的 loading 所有权或改写列表。

用户手动滚动时，路由可调用 `cancelWindowChange()` 取消尚未安装的日期窗口或返回最新请求，保留当前记录和两端游标，丢弃迟到结果；已失败的窗口替换也会清理其重试和错误状态，避免取消后再次跳回旧目标。普通历史分页及其失败重试不受该取消操作影响。分页游标修复只使用 SDK 已确认的历史窗口成员，避免刚完成发送的保留消息跨过尚未加载的记录。

`date_jump/chat_date_window_controller.dart` 协调 SDK 消息窗口与公共 viewport 的定位。`retry()` 重走失败的完整日期跳转（恢复同一目标并定位）或返回最新（合并实时缓冲并滚到最新），不重复日期搜索；普通分页失败回退 timeline 的对应方向重试，到达最新后再合并缓冲。只有当前请求的失败可以保存动作；新动作、成功、手动取消及关闭会清理旧失败，旧请求结束不能覆盖新请求的状态或重试目标。

历史窗口状态下的同步/前台 `refresh()` 保持当前窗口，由现有 SDK 实时回调处理回执及删除；它不请求最新页，避免跳回最新或制造历史缺口。失败重试保留操作类型及日期目标。历史和定位中窗口不写入最新首屏缓存，关闭后原安全缓存仍可供下一次进入使用；私密模式变化、删除与账号失效仍按原规则清理缓存。

关闭时刷新安全快照、停止列表观察和缓存计时器、关闭历史请求接收。SDK 回调和订阅仍由 ChatLogic 按原有所有权清理，避免旧页面关闭影响后继页面。

日期定位优先使用当前窗口已加载的当天记录（包括 SDK 无法搜索的消息类型），否则只在当前会话查询 SDK 支持搜索的消息类型，跳到当天的一条记录，可继续加载前后文。日界线使用本地午夜，SDK 请求单位是秒，消息时间是毫秒；过滤包含式查询的次日午夜，跨夏令时用相邻午夜计算时长。SDK `totalCount` 仅表示本页条数；仅当整页都是边界消息或已移除消息时继续翻页。页面关闭、会话清空、账号/令牌变化后丢弃迟到结果，重复点击不叠加弹窗或查询。

验证入口：`test/pages/chat/history/` 和 `test/integration/chat/`，覆盖真实 ChatLogic 初始化、首屏预读复用、发送状态与对象身份、私密过滤、账号/令牌/epoch/会话清理版本、清空/关闭晚到结果、同步合并和分页窗口。

## 高频消息与恢复

- 从后台回到原聊天页时先读取最新页；原生唤醒完成后再次协调读取，避免首次查询早于 SDK 入库却被当成已恢复。`chat_latest_message_recovery.dart` 在会话最新消息不在当前列表或缓冲区时延后 100ms 核对并补读；同一条消息尚未落库时再间隔 1 秒、3 秒核对，最多三次。正常实时回调先到则不增加查询。仅摘要到达、路由被覆盖或同步中的情况，在恢复可见/同步完成后重新检查；历史窗口不被替换。失败读取转交保留原动作的错误重试，不能持续自旋。验证见 `test/integration/chat/chat_foreground_recovery_test.dart` 与 `chat_recovery_overlap_test.dart`。
- 排队刷新真正开始后释放排队标记；若这次读取期间又出现持久化/唤醒事件，可再保留一次后续读取。覆盖页面后的新消息推进独立版本，旧读取不能清除新一轮待恢复状态。清空记录使摘要恢复的旧请求失效，新摘要仍可开始自己的有限补读；迟到结果不能恢复已清除记录。
- 自动收消息、发送、附件预占和发送完成时，最新窗口保留最后 600 条；窗口外仍发送中或失败待重试的消息额外保留，完成后再次收敛。不会为了保留大量待发送记录反而移除最新成功消息。
- 选择消息、阅读旧记录和日期定位期间延后自动裁剪，回到最新且结束选择后补做一次；未发生自动收发增长时，用户主动翻页读取的历史不按此限制裁剪。裁剪仅释放 UI 快照，SDK 历史和双向分页继续保留。
- 阅读旧消息且达到上限后，沿用历史窗口模式，保留阅读位置；仅缓存最近 100 条实时消息快照。所有完整消息仍由 SDK 持久化，向新消息方向翻页或点击回到最新后读取连续区间。
- 重连拉取的新页面与旧窗口不连续时，正在读旧消息的用户留在原窗口。回到最新时丢弃 SDK 最新边界之前的缓冲快照，避免拼接不连续区间。
- 同步、历史加载、加载失败或历史窗口期间不自动清空整个会话未读；恢复前清除旧的 viewport 可见授权，重新绘制后才能确认已读。私密消息仍按真实可见内容确认。
- 公共 viewport 使用消息 ID 对应的 GlobalKey 保留可见气泡子树；仍允许 sliver 更换坐标原点，避免破坏原有滚动修正。

测试覆盖万条实时消息、离线大间隔保留阅读窗口、连续分页、发送状态、私密已读和可见气泡状态保留。离线新增消息的精确条数依赖 SDK 会话未读，未虚构离线入场计数。

## 已加载长列表的局部更新

- 回执模块维护一个随消息列表变化失效的 ID 索引。滚动可见区域变化只查找可见 ID；C2C 回执只查找本次确认的 ID，无变化的回执不发布列表刷新。替换、撤回、删除后立即释放旧索引，关闭路由时注销观察并清空索引。
- 普通消息时间分隔继续按距上个显示时间六分钟计算，但仅在 `showTime` 变化时复制消息元数据。已读、状态或头像刷新无需为每条记录重新分配 `exMap`；时间变化、插入和删除仍会重新校准边界。
- 用户主动翻页的合并去重仍沿用 SDK 数据。2026-10-11 增加受页面资格约束的双向 600 条窗口，裁剪远端展示对象并保存回读游标，不删除 SDK 历史；本轮按用户要求未运行构建或测试，新增窗口策略的滚动锚点、反向分页与多选边界尚未运行验证。

后台恢复补充（2026-10-14 更新）：恢复连接只刷新最新窗口，不再保存旧消息位置并向后遍历全部离线历史。沿用 1 秒、3 秒两次有限重查与请求合并，避免首次查询早于入库；网络恢复或原生同步完成可以刷新重试预算。


### 大群历史按需读取（2026-10-14）

最新窗口与正在浏览的历史窗口保持分离。用户停在历史位置时保留滚动位置并缓冲实时消息；只有主动翻页或返回最新时移动窗口。清空、关闭与切换账号使旧响应失效。离线未读以 Core 的服务端读水位为准，不通过遍历下载全部未读消息计算。列表仍采用 600 条窗口及 100 条实时缓冲，待发送/失败消息单独保留。Core SQLite 对可再次拉取的普通消息实施每会话 1,000 条、账号 20,000 条和约 64 MiB 内容预算；这不包含媒体原文件与必须保留的发送状态、撤回/删除记录。回归覆盖见 `chat_foreground_recovery_test.dart`、`chat_background_gap_test.dart` 和 `chat_message_loss_matrix_test.dart`。
