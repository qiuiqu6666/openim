# 群通知分页

`GroupApplicationPager` 负责两个 SDK 群申请列表的 offset 分页及按时间合并。
收到的申请与自己发出的申请分别以 `count: 20` 读取，保留各源未展示的尾部，
每个页面批次最多返回 20 条去重记录，不能把两个来源各 20 条直接拼成 40 条。
身份沿用 `IMUtils.buildGroupApplicationID`，排序沿用申请时间倒序。
依赖 SDK 每个来源按申请时间从新到旧分页；真实部署的分页顺序仍需联机确认。

读前 fork 分页快照，只在完整读取成功且当前请求、账号、token 和页面仍有效时提交。
失败不会推进当前 offset，刷新替换旧分页器，迟到的旧请求无法覆盖新列表。
列表刷新重新填充已加载批次数，保留已加载范围；底部追加不重建路由或重置滚动。
SDK 应用变化订阅及审批后的服务器刷新保持原有入口，处理人/邀请人资料继续批量读取，
翻页保留之前页的资料缓存。只把已展示的收到申请记录标为看过。

页面复用 `SmartRefresher`、`IMViews.buildHeader` 和库内 `ClassicFooter`，下拉刷新、底部加载，
`group_application_footer.dart` 配置已有库的本地化状态与主题文字，只在加载时转动，
失败页脚可重试，没有更多时结束。未新增接口或自造生产数据。
参考 99chat 群申请列表展示，分页请求保持 OpenIM SDK 数据源。

测试：`test/pages/contacts/group_requests/group_application_pagination_test.dart`，
以及亮暗主题页面、审批与处理人原有回归。真实服务器及物理手势尚未真机验证。

2026-10-10 验证：群通知模块 32 项测试通过，本模块及其测试的 Flutter 静态检查无问题。
包括两个来源的有序合并、重叠去重、分页失败后相同 offset 重试、刷新/关闭使旧请求失效，
以及日夜主题下真实页脚回调的 20→40→45 条追加和滚动位置保留。
