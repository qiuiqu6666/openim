# 用户详细资料

正文参考 `E:/openim/reference-99chat/lib/src/user_profile.dart` 的移动端详细资料分支；顶部复用公共包的 `GlassAppBar` 实色模式，与页面背景使用同一颜色，不叠加玻璃效果。导航保持固定，初始内容按真实状态栏与导航高度留出空间。

## 维护入口

- `user_profile_panel_view.dart`：本人、好友、陌生人及群成员的页面协调与现有业务入口。
- `user_profile _panel_view.dart`：旧导入路径的兼容导出，路由已使用新入口。
- `user_profile_tokens.dart`：此页面专用的 99chat 间距、颜色、字号与圆角；不更改全局主题。
- `widgets/user_profile_identity.dart`：头像、姓名、性别、聊天号和签名的布局，不依赖 SDK 或控制器。
- `widgets/user_profile_quick_actions.dart`：三等分且等高的语音、视频、消息操作；页面传入原有控制器回调。
- `widgets/user_profile_load_state.dart`：好友关系尚未确认时的加载与重试，避免首帧误绘陌生人布局。
- `user_profile _panel_logic.dart`：现有 OpenIM 资料、好友、共同群、聊天背景与 SDK 生命周期。本轮保持原有订阅和导航所有权。
- `identity/group_profile_account_state.dart`：当前群资料页的公开账号读取与请求代次；只接受群成员接口里匹配群和用户的 `account`，不写入通用资料或好友缓存。
- `adding/profile_friend_add_account_resolver.dart`：单聊资料的公开账号添加准备；复用正式账号搜索并核对目标 IM 身份，绑定页面创建时的登录会话，关闭或会话变化后拒绝迟到结果。
- `../../moments/privacy/widgets/moments_peer_privacy_controls.dart`：好友的两项朋友圈隐私设置，委托朋友圈仓库完成真实请求与本机确认记录；不读取 GET settings 中不存在的名单。

卡片与列表复用设置模块的 `SettingsGroup` / `SettingsCell`；头像继续用 `AvatarView`，星标继续用 `StarBurstButton` 与联系人状态。新增两种布局组件只承担资料页面特有的身份排版和三等分快捷操作，不创建另一套通用卡片、行、头像或导航组件。

## 行为与数据

展示和复制使用公开业务聊天号 `account`，SDK、聊天背景、朋友圈和权限请求仍使用真实 OpenIM `userID`。群接口未披露的聊天号保持隐藏；本人没有对他人的通话、星标、共同群或黑名单操作。共同群计数区分真实 0、加载和失败；共同群聊分组只在好友资料显示，非好友资料（含群内陌生人）隐藏整个分组，好友关系变化时由现有响应式状态更新。

群成员资料页的账号来自 [群身份模块](../../chat/group/identity/README.md) 的 IM 原始接口 `/group/get_group_members_info`，包含从群内打开的好友和本人，每次打开都独立请求。`lookMemberInfo=0` 时群成员均可得到已有的公开账号；`lookMemberInfo=1` 时仅群主、管理员和系统管理员可得到。客户端只显示匹配群与成员的 `data.members[].account`，缺字段时隐藏聊天号，不补 IM 号或通用资料缓存。非群资料页仍使用原有公开账号来源。入群时间和邀请人继续通过 SDK `getGroupMembersInfo` 获取；SDK 成员模型不提供 `account`。所有导航、群操作及 `group/manage` 加好友凭证中的目标仍为原始 IM `userID`。

添加入口与实际提交共用 `FriendAddRequest.canSend`。单聊资料里的“添加好友”使用当前可见公开账号自动调用正式账号搜索；只有搜索结果的公开账号及原始 IM `userID` 都匹配当前目标，才直接进入申请页，来源为 `account`，无需跳转搜索页。缺少公开账号或匹配失败时留在资料页并提示，不猜 IM 号或昵称，也不伪造邀请。具有完整搜索、邀请或群信息的来源仍按原流程进入申请页；用户提交申请时才换取并核销凭证。

准备申请及申请页覆盖期间禁用重复点击。目标、公开账号、好友关系、黑名单、群权限、登录账号、SDK 账号、chatToken、服务器或页面状态变化后，旧准备结果不能导航或提示。新增的账号查询职责放在 `adding/`，原控制器仅保留页面条件检查和导航协调。

群规则、本人角色或本人资料更新时先清账号，再重新查询；本人资料更新覆盖系统管理员资格变化，不依靠成员角色推断可见账号。回到前台同时更新群资料、本人角色和账号。开关变化不会推动成员版本号，因此不以 SDK 缓存或增量游标维持旧账号。离群、目标移出、页面关闭及会话变化会拒绝旧响应。群内加好友保护另读 `friend-protect` 的 `protect`，不从 `applyMemberFriend` 或 `lookMemberInfo` 推断。

账号状态已拆入独立子目录。原控制器仍协调既有 SDK 资料、权限通知和页面生命周期；此次保留其兼容入口，局部加请求守卫，不改变其他流程的所有权。

好友正文按参考分组：备注与朋友圈及两项朋友圈权限、共同群与聊天背景、黑名单。分享、删除和黑名单的确认继续使用原流程。头像支持预览；群加入时间统一归一为毫秒显示。

朋友圈开关只呈现此设备的成功确认记录。保存成功后旧朋友圈内容立即失效；失败保留原状态及原操作重试；本机保存失败只补写记录。跨设备未缓存的取消仍可以在现有朋友圈权限名单页选择好友完成。

保留蓝色主操作及白色文字，并将主按钮蓝色调整到满足普通文字 4.5:1 对比度。聊天号胶囊保持参考的紧凑外观，透明点击区域至少 48px；大字号时自然扩展。

进入页面时只使用当前登录会话的联系人目录正向确认好友，不以无联系人记录或全局资料缓存判断陌生人。SDK 继续验证真实关系；未知关系确认前不展示陌生人底栏，失败可以重试。好友新增与删除订阅跳过已经缓存的首次重播，之后的实时事件正常更新关系。聊天号区域与两行签名按当前字号预留空间，包含群接口尚未返回或未披露账号的资料页；空账号没有复制入口、图标或可访问语义，布局占位按相同字体、边框和触控高度测量。后续资料补齐不改变头像或下方卡片位置。迟到查询通过请求代次、账号、token 和关闭状态检查，避免覆盖新关系。
