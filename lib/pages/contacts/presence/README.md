# 官方账号在线展示

`contact_presence_policy.dart` 在展示层统一解析联系人状态：固定服务账号
`assistant`、`99Message`、`99Pay`，以及非空用户 ID 且 SDK 用户资料 `ex`
解析为 `{"accountType":"official"}` 的账号，始终提供「在线」展示状态。
昵称、备注、无效 JSON 或仅有 `officialRole` 不作为官方身份依据。

复用既有 `OfficialAccount` 的身份判断、`UserPresence` 的翻译文案和
`PresenceLabel` 的显示偏好。普通用户直接使用原状态对象，最近上线时间、
隐私隐藏和全局在线状态显示开关保持原规则。

通讯录、好友/名片/建群选择、历史发送者、群成员列表、普通单聊标题和
会话长按预览共用此策略。已有官方通知页保持原在线标题，AI 助理页保持
「官方助理 · 你的专属对话」及正在回复提示。历史发送者复用原 SDK 查询
带回的 `ex`，不新增用户查询或状态订阅。

策略不修改 SDK 在线状态或服务端 presence，官方展示继续在线；页面
现有的账号、路由、可见性和偏好检查保持不变。

状态展示复用本地 99chat 联系人两行列表的现有字号、间距与亮暗主题，
本次仅改变官方账号的状态解析，不调整布局。测试位于
`test/pages/contacts/presence/`，真实页面回归覆盖通讯录、好友选择、
历史发送者和会话预览；实际执行结果见
[验证记录](../../../../docs/official-account-presence-validation.md)。

## 聊天头部状态稳定性

普通单聊沿用 `ContactsLogic` 的可见用户订阅和 `PresenceStore` 的账号缓存。
进入/退出资料或聊天页只增减订阅所有者；同一个用户已经被订阅时，不因
新增所有者重新订阅或强制刷新。恢复前台、SDK 重连和同步完成仍执行刷新。
退出页面保留已确认的状态，释放订阅时使在途结果失效。
首次查询失败、还没有状态快照时，新所有者进入会重试查询，已有 SDK 订阅
继续复用，不会因去重而一直留下空状态。

SDK 的在线/离线事件仅触发既有 `/chat/users/presence` 查询。同一批 120 ms
内的事件合并为一次查询，接口一起确认在线状态、最近在线时间及隐私。
等待期间保留最近一次成功结果，不先生成「刚刚在线」再覆盖为实际时间。
结果校验用户、chatToken、请求版本和关闭状态，失效结果不会更新展示。
收到新事件会立即使旧请求失效，即使它在批次查询前返回也不会覆盖状态。
后台停止接收和执行状态批次，回到前台后由原刷新流程补齐。

`TitleBar.chat` 的单聊状态行一直占位；未知状态或关闭显示偏好时文本为空，
没有虚构状态或旧文案语义。头像、昵称和状态行在状态变化时保持位置。
`ChatPage` 与标题栏共享按字体缩放计算的高度，避免大字体溢出。
实际执行结果见 [稳定性验证](../../../../docs/chat-header-presence-stability-validation.md)。
