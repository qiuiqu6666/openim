# 共享支付密码面板

`PasswordPaymentSheet<T>` 管理输入密码、支付中和成功展示；`showPasswordPaymentSheet<T>` 复用现有 Material BottomSheet 路由，返回业务接口确认的 `T`。组件不依赖资金模型或具体业务接口，红包、转账以及后续缴费、续费均可提供自己的摘要与支付回调。当前已接入的真实业务是红包和转账；本项目尚无缴费、续费接口。

## 状态与布局

关闭按钮统一位于右上角，标题在弹窗内独立居中；不改变金额、密码区或键盘位置。

- `enteringPassword`：数字键盘输入或粘贴满六位后，立即调用 `onPay(password)`。同步切换状态后才调用回调，同帧的点击、粘贴及辅助操作不能重复提交。
- `processing`：保留标题、摘要与六格密码；整个键盘替换为居中的 30pt 圆环和次级文字「支付处理中…」。键盘区域始终保留四行高度及底部安全区；输入、摘要内按钮、取消、返回、遮罩关闭与拖动均不可操作。
- `success`：仅在 `onPay` 成功返回后，展示 32pt 简洁勾选与「支付成功」，默认 900ms 后关闭并返回结果。勾选动画尊重减少动画设置。`onSuccess` 立即触发刷新，刷新延迟或异常不延长成功展示，也不使支付重新可提交。
- 请求异常：先清空密码再恢复输入，显示业务错误并复用 `IMViews.showToast`；键盘和原弹窗恢复，用户可重试。错误文字占位高度固定。`errorMessage` 提供可操作提示，未知异常使用「支付失败，请重试」，不直接展示服务器内部异常。

颜色来自 `AppTokens` 和当前主题。圆环扩展现有 `LoadingView.indicator`；密码格和键盘沿用已有实现，其唯一实现现位于本目录，设置页旧路径保留导出以兼容交易密码设置流程。未找到已有独立且无装饰的成功状态组件，因此成功勾选由此共享面板统一持有，不新增全局覆盖层。

付款方式可通过 `summaryBuilder` 和 `onChangePaymentMethod` 扩展。选择期间同步禁止输入、提交及重复打开选择器，保持原面板高度；回调返回 `true` 才清空密码并重建摘要，取消则保留原密码与付款方式。`canChangePaymentMethod` 由业务方在每次重建时校验，处理期间、成功状态及尚未确认的原交易都不提供可点击入口。选择异常使用原错误与 Toast 通道，组件仍不依赖币种或资金模型。

## 业务与生命周期边界

`onPay` 必须返回已确认的业务结果，负责真实 API、账户与服务器校验、持久幂等编号，以及超时后的原单确认。组件只保证同一面板的一次在途请求，不能替代服务端幂等。密码仅留在当前控制器与请求参数中，不持久保存。异步结果不能恢复已退出的面板；成功定时器只关闭自身路由，不能误关覆盖它的新页面。

资金适配层为 `pages/fund/widgets/fund_pay_sheet.dart`，提供金额、可切换的钱包摘要和错误映射，选择器复用原 `FundPayMethodSheet`。`pages/fund/payment/fund_payment_draft.dart` 保存只读业务快照，切换币种保持原数字金额和收款人/备注，使用新单号，校验小数位、整数范围及拼手气红包最小分配额；不做兑换或静默四舍五入。`FundSendPage` 持有选择、账号和支付生命周期，合并在途调用并缓存已支付订单；本地清理或刷新失败不能重新扣款。超时后的原交易禁止切换币种，重试仍使用原单号和快照。返回订单继续复用聊天资金状态更新链路。支付途中改变账户或服务地址时，不向失效会话返回原订单。

状态和路由保护留在同一组件内，避免将授权锁、动画和关闭计时器拆给不同所有者。纯密码展示、键盘、文案和尺寸已独立。

## 验证

`test/widgets/payment/password_payment_sheet_test.dart` 使用与资金无关的泛型结果验证三态位置不变、30pt 圆环、固定键盘空间、同帧重复输入、错误恢复、慢刷新、关闭限制与迟到响应；另覆盖日夜主题、小屏、横屏和大字号。资金业务测试位于 `test/fund_send_page_test.dart`，原交易密码设置回归位于 `test/trade_password_page_test.dart`。预览使用模拟数据，不能替代真实资金账户及 iOS 真机联调。
