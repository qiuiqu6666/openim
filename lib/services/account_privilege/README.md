# 当前账号特权展示权限

唯一来源是当前用户以自己的 Chat token 调用聊天服务 `POST /user/find/full`，读取匹配 `userID` 的完整资料。`UserFullInfo.isPrivileged` 仅接受布尔 `true`；缺失、null、字符串和数字都按关闭处理。SDK用户资料、登录响应、群角色、用户自定义ex及其他人的搜索结果不会授予当前账号特权。

`AccountPrivilegeRuntime.store` 由登录后、应用返回前台、进入群聊、打开群功能面板、进入用户详细资料和进入三公页面前刷新。相同群聊绑定的普通重建不重复请求，并发刷新合并为一次请求。请求失败或资料不匹配清除展示权限；账号、Chat token、服务地址、退出登录或销毁后的旧响应不能重新开启权限。验证通过的false响应同样生效，后续true响应不会复活此前已失效的操作。

`AccountPrivilegeAccess` 提供可注入的只读展示权限与刷新入口，测试显式提供测试授权源。`GroupFeatureContext.privilege` 默认使用当前账号运行实例；群功能仓库监听其变化以刷新入口，三公运行时和请求适配器把它与既有群业务能力、租户和权限版本同时校验。

群聊三公运营／代理工具箱及代理浮窗的展示读取已确认的账号特权；其中三公代理工具箱与「查／团／个／隐」浮窗另需群类型 `gameType=4`，普通群及其他类型默认隐藏；图示运营浮窗另外要求群资料 `ex` 根对象的数字 `gameType=1`，并尊重用户保存的隐藏设置。类型为普通群、六合彩或缺失／非法时隐藏运营浮窗。类型为 1 时，缺失群摘要、绑定或业务能力不会隐藏该发现入口；点击后先读取最新业务权限，失败或拒绝时展示原因与重试，不据群类型或账号特权补造业务权限。公开入口的加载／错误页不冻结旧业务权限版本，获准后才创建保留版本隔离的私人业务页面。

用户详细资料中的“三公服务”同样只看当前登录账号特权；与目标用户的共同群数量无关。空群列表、旧三公字段缺失、绑定或权限服务错误保留服务卡与重试，显示已有管理／流水功能但暂不可操作；目标用户的私人报告和实际写操作仍要求对应群业务能力与已确认租户。

三公特权路由、弹窗及底部面板在关闭后退出；普通聊天和用户资料页面仅移除特权区域。客户端不调用管理端口10009的`/user/privilege/set`，不在注册、导入或资料编辑中开启特权；该设置仍只能由后台管理员执行。

此字段用于客户端展示，不能替代服务端权限校验。后台切换后，下次成功刷新才会获得新值，当前不假设实时推送。
