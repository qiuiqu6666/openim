# 应用内网页

应用在 `AppView` 安装 `InAppBrowserHost`，让网页位于业务导航之外。收起后切换、返回或替换业务页面都不会重新创建 WebView，展开继续使用原控制器、历史和滚动位置。未安装 Host 的独立组件环境继续使用原路由入口。

系统返回处理在 `main` 中先于 MaterialApp 安装：展开时优先回退网页历史或关闭，收起时交给业务导航。应用内分享期间暂时隐藏浏览器层，结束后恢复原实例；退出账号时清除网页。当前同时保留一个网页，打开新的外链会替换它。

公开入口为 `openInAppBrowser(uri, context: context)`，无上下文的聊天/扫码动作可使用现有 GetX 根导航。返回值表示页面是否已入栈，不等待用户关闭网页。

复用现有 webview_flutter、AppTokens 和 Material 导航控件；对照 99chat 的 privacy_webview.dart 内嵌网页结构，扩展为跨模块通用外链页。网页内容直接来自目标网站，不注入 IM token、用户资料或原生 JS 桥接。

- Android/iOS 使用内嵌 WebView；其他平台显示不支持提示，不自动跳转外部浏览器。
- 仅允许无用户凭据的 HTTP/HTTPS 地址，重定向也经过检查，不唤起外部应用。
- 使用保留顶部安全区的圆角弹层，顶部显示当前网址和“完成”；完成直接关闭，系统返回优先回退网页历史，无历史时退出。底部前进/后退按钮根据历史启用，刷新保留历史，加载失败重试创建新视图。
- 底部分享通过 InAppBrowserShare 接入应用的联系人选择、ChatMessageSender 与账号会话保护，发送网页标题和链接，不唤起系统分享面板；仅用户主动点击“在浏览器中打开”时交给外部浏览器，网站重定向不会自动唤起其他应用。
- `InAppBrowserRoute` 联动网页上滑与底页缩小圆角，关闭时反向恢复；通过 Flutter delegated transition 同时兼容 GetX 和 Material 路由，不复制或重建底页。减少动画时直接完成自动过渡。按住顶部网址栏或底部工具栏下拉时，新页跟手移动、底页同步恢复；超过屏幕高度的 25% 或快速下滑收起为底部网址条，否则回弹。收起后保留 WebView、历史和页面状态，移除遮罩以操作底页，并为底条预留空间；点击网址或向上箭头重新展开，也可按住底条跟手上滑：达到展开距离或快速上滑即展开，不足则回到底条，点击关闭按钮释放页面。网页内容保留原生滚动手势，避免滑动网页时误关。
- 主文档加载错误及 30 秒超时显示恢复页面；子资源错误不阻断网页，旧视图和销毁后的回调不写入状态。
- 原生页面外壳支持亮暗主题、安全区域和文字缩放；网站内容遵循网站自身主题。
- 电话、邮件、分享唤起、附件下载和安装更新不属于普通网页浏览，保留其专用处理。

测试：应用根目录 `test/widgets/in_app_browser/in_app_browser_test.dart`，使用项目现有 WebView 平台假实现方式覆盖导航、协议限制、重试、生命周期、亮暗主题及小屏大字。
